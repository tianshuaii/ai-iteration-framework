# 能力、Skills、MCP 与证据

框架使用四层分工，避免把可选工具误当成阶段事实源：

1. `status.md` 保存唯一动态进度。
2. Ruby 脚本执行可确定的结构、摘要、审批和证据门禁。
3. Skills 描述阶段工作流、判断方式和产物格式。
4. MCP 提供实时事实或受控动作，默认只读。

稳定能力登记在根目录 `capabilities.yml`。某轮实际使用哪个提供者、版本、输入摘要和证据路径，写入该轮 `capability-log.md`。能力不可用时先使用登记的降级提供者；必需能力仍无法产生可信证据时，把 `work_state` 设为 `blocked`，不能写成通过。

## 三级工作流

`status.md` 的 `workflow_profile` 保存本轮档位，选择条件只来自 `capabilities.yml`：

- `lite`：全部复杂度字段明确为 `no`。需求和计划都可以用确定性清单记录 skipped。
- `standard`：没有高风险条件的普通产品代码。非简单需求执行一次设计访谈；计划阶段不重复访谈，由计划评审检查任务、风险、测试和资源隔离。
- `strict`：接口或 Schema、数据库或迁移、安全权限、并发、性能、多仓库、外部服务、部署、破坏性操作，或任一不确定项。需求和计划阶段都执行设计访谈。

档位只能提高，不能低于当前复杂度证据要求。三个档位都必须经过需求审批、计划审批、迭代级统一代码审核、真实测试验证和最终交付评审；档位不扩大任何写入授权。

## 设计访谈

需要访谈的阶段首选 `grill-me`，不可用时使用仓库 Skill `iteration-design-interview`。事实由 Agent 查询，决策由用户作出。访谈按轮次提出当前能回答的全部问题，每题附推荐答案、主要替代方案或影响和可直接复制的回复。任何等待用户的消息都必须同屏重复 `Qxx` 问题全文，不能只给编号或只给回复口令。standard 计划阶段的 skipped 不是取消计划审查，`iteration-plan-review` 仍是审批前必需门禁。

用户直接回答结构化访谈问题时，只授权更新当前轮的 `design-interview.md`、`status.md` 和对应阶段文档；不授权产品源码、提交、推送、部署、迁移或任何外部写入。

访谈历史保留在 `design-interview.md`。新尝试使用 `inline-confirmation-v1`：未确认行固定为 `待确认 / pending / 无`，收到直接用户回答后才写 `resolved`，并在确认依据列保留 `用户原话：...`。受保护输入变化后旧尝试标记为 `superseded`，只重问受影响分支。未决问题必须为零；用户明确接受的假设或残余风险可以成为已决事项。

## 能力证据

能力执行索引写入 `capability-log.md`，详细内容放在 `evidence/`。索引至少记录能力、阶段、任务、提供者、版本、状态、输入 SHA-256、证据路径、起止时间和 P0/P1/P2 未处置数量。为了避免同一事实重复抄写，多个能力可以索引同一份分节报告：

- `evidence/analysis/stage-review.md` 合并需求评审和计划评审。
- `evidence/reviews/<task-id>.md` 保存每条任务写入前的实现守卫。
- `evidence/reviews/implementation-review.md` 合并全部任务后的检查、整轮代码审核、修复和复验。
- `evidence/delivery/final-review.md` 合并测试验证和交付复核。

共享文件不等于合并门禁；`capability-log.md` 仍为每项能力保留独立记录、摘要、时间和发现计数。

新轮次使用 `task-guard-digest-v2`：implementation guard 的 `input_digest` 由当前 `T-xx` 完整任务行、`change-scope.md` 和 `workspace.md` 计划审批区生成。任务完成勾选被规范化，其他任务的新增或修改不会令本任务守卫过期；本任务正文、共享改动范围或计划检出/资源区变化仍会要求重新守卫。旧日志继续按产生时的 v1 证据兼容，统一代码审核仍绑定最终整轮计划摘要。

代码审核使用 P0-P3：P0/P1 必须修复，P2 必须修复或明确处置，P3 可选但保留。首次进入验收前建立 `task=无` 的整轮审核基线；验收返工只追加守卫之后的 `task=T-xx` 增量审核。校验器验证审核覆盖链、摘要、路径和阻塞项，不接受单独的“已使用 Skill”声明。

## MCP 权限

MCP 默认只读。评论、提交、推送、部署、数据库变更、工单变更和其他外部动作仍需当前请求中的单独授权。总控 Skill 只能选择能力和汇总证据，不得扩大工具权限或替用户完成审批。

MCP 名称在 `capabilities.yml` 中以能力别名登记，不要求每台机器安装同名服务。可选 MCP 不可用时使用登记的本地或文档降级方式；若当前门禁确实依赖无法取得的事实，则阻塞并写明需要的证据。
