# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | 普通 HTTP 直通返回上游状态与正文时，raw response 同时包含 Fastify 已生成的 `Access-Control-Allow-Origin`。 | 通过 |
| AC-02 | TC-02 | 平台登录上游 `code != 200` 时，保持上游状态、端到端响应头和原始正文，并同时包含 BFF CORS 头。 | 通过 |
| AC-03 | TC-03 | 上游提供同名 CORS 头时，最终响应仍使用 BFF 根据当前请求生成的值。 | 通过 |
| AC-04 | TC-04 | 平台登录 `code == 200` 的绑定查询、Session 创建和标准登录响应不受影响。 | 通过 |
| AC-05 | TC-05 | 普通代理仍以流方式转发，不新增整段响应缓冲，也不修改现有全局 CORS 配置。 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写受控豁免。
