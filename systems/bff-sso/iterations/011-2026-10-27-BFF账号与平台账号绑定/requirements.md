# 需求与注意事项：BFF账号与平台账号绑定

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

当前 Admin 前端只有一个“账号”页，管理系统统一登录主体；系统已有子服务和子服务接口清单，但没有“接入平台”概念，也没有 BFF 账号到外部平台账号的绑定关系。

## 本次要做

### 页面

1. 将 Admin 前端现有“账号”菜单、页标题和页面说明改为“BFF 账号”。
2. 新增“接入平台”页，用于查看和创建接入平台。创建时填写平台名称、多选所属子服务、选择登录接口所在的子服务，再选择该子服务的登录接口。
3. 新增“平台账号绑定”页，手动选择 BFF 账号和接入平台，并填写平台账号 ID。

### 接口与保存

1. Admin 前端继续只请求 BFF，不直连 Admin 后端或子服务。
2. 平台保存时，登录子服务必须属于该平台已选子服务；登录接口必须来自选定登录子服务当前可用的接口清单。
3. 绑定页手动录入平台账号 ID，不从外部平台拉取账号列表。

### 数据

1. 新增系统接入平台表、平台与子服务关联表、BFF 账号与平台账号绑定表；系统表使用 `sys_` 前缀，关联表使用 `_link` 后缀，全部字段有注释并保留 `yn` 软删除标记。
2. 同一个 BFF 账号在同一平台最多绑定一个平台账号 ID，但可在多个平台各绑定一个账号 ID。
3. 同一平台下的同一平台账号 ID 最多绑定一个 BFF 账号。
4. 唯一性必须由数据库约束与服务端校验共同保证，不只依赖页面校验。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 新建接入平台 | 名称、子服务、登录子服务和登录接口均必填。 |
| 新建账号绑定 | BFF 账号、接入平台和平台账号 ID 均必填。 |
| 已有 BFF 账号 | 保持现有登录、启停、设密和软删除行为；不自动创建平台绑定。账号禁用或软删除后保留旧绑定并显示“BFF 账号已失效”，禁止为失效账号新建绑定，不阻止账号操作且不自动解绑；禁用账号重新启用后旧绑定恢复有效。 |
| 已有子服务 | 保持原有接入、运行包和转发行为；只作为平台选择项。 |

## 不做

- 不修改现有 BFF 账号密码格式和登录会话机制。
- 不从外部平台同步平台账号列表。
- 不自动迁移或推测已有账号的平台绑定。
- 不在本轮实际调用外部平台登录接口，不保存平台密码、Token 或其他凭据。

- 文件列表见改动范围，这里不重复贴路径。
