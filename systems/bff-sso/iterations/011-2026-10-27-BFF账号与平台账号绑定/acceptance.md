# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | Admin 菜单与页面将现有“账号”明确展示为“BFF 账号”，原列表、筛选、新建、编辑、启停、设密和软删除行为不变。 | 通过 |
| AC-02 | TC-02、TC-03 | 超管可列出、新建和编辑接入平台；名称、子服务、登录子服务和登录接口必填，登录子服务/接口归属不一致时前后端均拒绝保存。 | 通过 |
| AC-03 | TC-04 | 接入平台只能软删除；存在有效账号绑定时删除被拒绝，解绑后可删除。 | 通过 |
| AC-04 | TC-05、TC-06 | 超管可新建绑定、修改平台账号 ID 并软删除解绑；编辑不能换 BFF 账号或平台。 | 通过 |
| AC-05 | TC-07 | 同一 BFF 账号在每个平台最多一个有效绑定；同一平台账号 ID 在同一平台最多属于一个 BFF 账号；并发请求也不能绕过约束。 | 通过 |
| AC-06 | TC-08 | 登录子服务或接口失效时，平台和旧绑定保留并显示“登录配置已失效”，新建绑定被拒绝；BFF 账号禁用或软删除后旧绑定保留并显示“BFF 账号已失效”，禁止新增绑定且不影响原账号操作，禁用账号重新启用后旧绑定恢复有效。 | 通过 |
| AC-07 | TC-09 | 新页面和写接口仅允许启用的 `SUPER_ADMIN`；未登录、非超管或失效会话不得访问。 | 通过 |
| AC-08 | TC-10、SR-01、SR-02 | 三张新表符合 `sys_`/`_link`/`yn`/字段注释约束，迁移只在 Admin 后端；现有 BFF 账号登录管理、子服务列表和接口查询不回归。 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。
