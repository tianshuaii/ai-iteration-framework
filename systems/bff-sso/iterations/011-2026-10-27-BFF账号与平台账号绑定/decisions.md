# 决策记录

| 编号 | 决定 | 原因 | 没采用的做法 |
|---|---|---|---|
| D-01 | 一个 BFF 账号在每个接入平台最多绑定一个平台账号 ID，可跨多个平台各绑定一个。 | 用户已明确绑定基数。 | 允许同一 BFF 账号在同一平台绑定多个账号。 |
| D-02 | 同一平台下的同一平台账号 ID 只能属于一个 BFF 账号。 | 用户已明确平台账号不得重复绑定。 | 只在页面阻止重复，不加数据库约束。 |
| D-03 | 平台账号 ID 由管理员手动录入。 | 本轮需求是手动绑定，现有系统没有通用外部账号列表合约。 | 调用每个外部平台各自的账号列表。 |
| D-04 | 登录子服务必须包含在平台已选子服务中，登录接口必须属于该子服务。 | 避免平台组成和登录配置相互矛盾。 | 允许登录接口指向平台以外的子服务。 |
| D-05 | 本轮只保存平台、登录接口和账号绑定配置，BFF 不实际调用外部登录接口。 | 用户确认 Q1；实际调用还需凭据、入参映射、Token 提取和失效策略。 | 在本轮同时实现外部登录。 |
| D-06 | 接入平台支持列表、新建、编辑和软删除；存在有效账号绑定时禁止删除。 | 用户确认 Q2；保证生命周期完整且不产生孤儿绑定。 | 只提供创建或强制级联删除。 |
| D-07 | 绑定可修改平台账号 ID 和软删除解绑；不允许原地更换 BFF 账号或平台。 | 用户确认 Q3；身份换绑通过“解绑后新建”保留清晰审计语义。 | 允许一条记录任意更换两端主体。 |
| D-08 | 仅启用的 `SUPER_ADMIN` 可使用新页面和接口。 | 用户确认 Q4，与现有 Admin 管理端权限边界一致。 | 向 `PLATFORM_STAFF` 开放配置能力。 |
| D-09 | 登录子服务或接口失效时保留平台和旧绑定，显示“登录配置已失效”并禁止新绑定。 | 用户确认 Q5；避免外部配置变化静默删数据。 | 自动删除平台或全部绑定。 |
| D-10 | “账号”改为“BFF 账号”只改用户可见名称，账号字段与原有操作不变。 | 用户确认 Q6；不将文案改名扩大成身份模型改造。 | 新建第二套 BFF 账号模型。 |
| D-11 | BFF 账号禁用或软删除后保留旧绑定并显示“BFF 账号已失效”，禁止为失效账号新建绑定，不阻止原账号操作且不自动解绑；仅禁用账号重新启用后旧绑定恢复有效。 | 用户确认 Q7；保持 Q6 确认的既有账号生命周期，同时保留绑定审计关系。 | 用绑定阻止账号禁用/软删除，或账号失效时自动解绑。 |
