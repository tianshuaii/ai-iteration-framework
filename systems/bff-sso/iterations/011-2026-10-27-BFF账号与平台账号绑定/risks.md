# 风险与回退

| 风险 | 影响 | 怎样避免 | 怎样退回 |
|---|---|---|---|
| Prisma Schema 无法表达只约束 `yn=1` 的 partial unique。 | 误用普通 `@@unique` 会让软删除后的合法重建失败；只做先查后写又会被并发绕过。 | 唯一性只由 Admin migration SQL 建 partial unique，BFF 同步关系模型并捕获 `P2002`；用静态迁移检查和并发用例双重验证。 | 迁移执行前可回退模型和代码；执行后通过单独授权的迁移回退或数据库备份恢复，不物理删除业务数据。 |
| 登录接口没有独立 endpoint 表，运行包替换后接口可能消失。 | 平台配置可能指向不存在的接口，若级联清理会丢失历史。 | 保存协议稳定键与显示快照，写入和查询时对照当前生效运行包；失效只标记并阻断新增绑定，不自动删平台或旧绑定。 | 回退动态判定代码即可恢复旧展示；记录本身保持不变。 |
| 平台子服务、登录配置和绑定分别写入导致半成功。 | 页面显示与数据库关系不一致，可能产生孤儿或绕过删除阻断。 | 所有平台/绑定写操作使用事务，平台关联采用软删旧关系后恢复或新建；外键使用 `RESTRICT`。 | 事务失败自动回滚；已提交的业务变更通过相应软删除或再次编辑恢复。 |
| BFF 账号或登录配置失效后普通关联查询把旧绑定过滤掉。 | 管理员无法看到历史关系，也无法判断为何不能新增绑定。 | 列表显式读取包含失效主体的旧绑定，再单独计算账号和登录配置状态；定向测试覆盖禁用、软删除、重新启用和接口消失。 | 回退列表状态拼装，不修改已有绑定数据。 |
| 新功能继续堆入既有超长 Admin 文件或 300 行账号页。 | 超过文件规模约束，审核和后续维护困难。 | 后端拆独立 Controller/Service/DTO，前端拆 Page/Modal/API/model/spec；现有大文件只做注册或文案级最小改动。 | 新模块可按任务整体回退，不影响现有账号与子服务功能。 |
| 新增路由只做前端隐藏或重复实现权限。 | 非超管可能绕过页面，或两套权限规则漂移。 | 复用 `AdminSessionGuard` 的启用超管校验，Service 只补被绑定账号/平台的业务状态校验。 | 回退新路由注册；现有 Admin 权限链保持不变。 |
| 共享检出中覆盖接管前未跟踪文件。 | 用户已有审核记录可能丢失或混入本轮成果。 | 明确排除 `adx-bff-backend/CODE_REVIEW.md`，实现前逐文件记录 HEAD 和 dirty，禁止 reset/checkout 覆盖。 | 若发生重叠立即停止并按接管前清单恢复，不自行删除用户文件。 |

## 发布与迁移授权边界

- 实现阶段只创建代码、迁移文件和测试，不执行数据库迁移。
- 启动本地服务、使用测试库、创建验收夹具、提交、推送、合并、拉取和部署均需分别取得明确授权。
- 正式迁移前必须记录目标环境、备份标识、操作者、时间与回退负责人；没有这些信息不得执行。
