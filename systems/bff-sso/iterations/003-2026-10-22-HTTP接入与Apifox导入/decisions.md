# 决策记录

| 编号 | 决定 | 原因 | 没采用的做法 |
|---|---|---|---|
| D-01 | 原接口 Apifox 项目 ID 只放在接口项目，字段名 `sourceApifoxProjectId`。接入服务不保存、不读取。 | 用户要求接入服务不感知这个 ID。它和「把运行包推到另一个 Apifox 项目」不是一回事。 | 把这个 ID 放在接入服务上，导入时再去读接入服务。 |
| D-02 | 不复用接口项目上已有的 `apifoxPushProjectId`。那一列仍只作为推送运行包时的后备项目。 | 现在推送会在接入服务没填 ID 时退回接口项目的这一列。拿它当拉原始接口的来源，会把两件事写成同一个 ID。 | 把现有列改成拉取来源，并取消推送后备。 |
| D-03 | 新建 HTTP 项目只保存 ID。拉取发生在「原接口文档」或「项目分支」点「导入接口」时，并和已有原接口做差异。只改项目名称或 ID 的保存不拉取。 | 用户要求新建是保存、更新才拉取。改个名称就全量重拉，会把没准备好的差异写进工作区。 | 一点保存就拉取；或者每次编辑项目都拉取。 |
| D-04 | 差异沿用现在导入 Proto 的做法：原接口进入工作区，改造和整合先出预览，确认后才改。 | 用户要求和原有接口做差异，后面的处理仍和 gRPC 一致。另做一套差异页会多出一条流程。 | 导入后直接改改造和整合，不给人确认。 |
| D-05 | 新建接口项目、新建接入服务的表单默认都是 HTTP。库列默认仍是 `grpc`。已有行迁移后仍是 `grpc`。 | 用户要求新建默认 HTTP。列默认如果改成 HTTP，旧程序没传这个字段时会把老数据或平台内建行改掉。 | 列默认也改成 HTTP；或新建表单仍默认 gRPC。 |
| D-06 | 接口类型创建后不能改。 | 一个项目里已经有一种文档。中途改类型会把 Proto 文档和 HTTP 文档混在同一分支。 | 编辑时允许改类型，并清空已导入接口。 |
| D-07 | HTTP 走 Nacos 时只用实例 metadata 的 `httpPort`。没有就失败，不改用 gRPC 端口。直连则把已有的 `directAddress` 拼成 `http://ip:端口`。 | 实例上的 `port` 现在用于 gRPC。拿错端口会把 HTTP 打到 gRPC 端口上。 | HTTP 也用实例的 `port`。 |
| D-08 | 正在使用的接口包和接入服务通信方式不一致时，转发失败。 | 接入服务只决定怎么打出去，不保存原始接口项目 ID。包和通信方式各说各话时，不能猜。 | 看到包是 HTTP 就忽略接入服务上的通信方式。 |
