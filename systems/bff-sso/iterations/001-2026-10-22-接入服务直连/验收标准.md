# 验收标准：接入服务可选直连

对应需求见 [需求与注意事项](./需求与注意事项.md)。每条都要能在 [测试用例](./测试用例.md) 里对上。未通过且未取得受控豁免的项目，不能把本次迭代标成已验收。

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | 新增弹窗里，接入类型在「子服务类型」下面、「Nacos 分组」上面。Apifox 项目 ID 和状态仍在 Nacos 相关字段下面。表单有失焦校验，标签后能看到必填星 | 通过 |
| AC-02 | TC-01 | 打开新增弹窗时，接入类型默认是「直接接入」，能看到 IP 和 gRPC 端口，看不到 Nacos 分组和服务名 | 通过 |
| AC-03 | TC-02 | 选「Nacos 接入」后，能看到 Nacos 分组和服务名，看不到 IP 和端口。服务名为空不能保存 | 通过 |
| AC-04 | TC-03 | 直接接入时，空 IP、空端口、主机名、IPv6、带 `grpc://` 的整段、前导 0、超出 0 到 255 的段、端口不是 1 到 65535 的整数，都不能保存，并有明确提示 | 通过 |
| AC-05 | TC-04 | 用直接接入保存成功后，列表发现方式是直连，并显示所填 IP 和端口。再编辑仍是直接接入。`nacosServiceName` 和 `nacosGroup` 为 null，`directAddress` 是 `ip:端口` | 通过 |
| AC-06 | TC-05 | 用 Nacos 接入保存成功后，列表发现方式是 Nacos，并显示分组和服务名。再编辑仍是 Nacos 接入，`directAddress` 为 null | 通过 |
| AC-07 | TC-06 | 编辑一条改前就存在的 Nacos 服务，打开时是 Nacos 接入，原分组和服务名还在。不保存就关闭，数据不变 | 通过 |
| AC-08 | TC-07 | 把一条 Nacos 服务改成直接接入并保存后，`/proxy` 转发连的是填写的 `grpc://ip:端口`，不再向 Nacos 要实例 | 通过 |
| AC-09 | TC-08 | Nacos 接入的转发与现在一致：按服务名选健康实例，一台失败会换另一台。直接接入失败不换地址 | 豁免：用户确认当前缺少第二台健康实例不阻塞本轮；残余风险是 Nacos 首台失败后换另一台未现场验证，直连失败不换地址已验证 |
| AC-10 | TC-09 | 连通测试弹窗的「发现方式」按记录显示。直接接入不出现「Nacos 实例」，改为所填 IP 和端口；Nacos 接入仍显示分组、服务名和实例 | 通过 |
| AC-13 | TC-11 | 页头说明不再只写 Nacos。列表「发现方式」能区分两种。筛选里选了某个 Nacos 分组时，直连服务不会出现。Nacos 行的空分组仍按 `MERGEX_GROUP` 筛选。后端找实例的空分组仍是 `MERGEX_FRONTEND_CONFIG_GROUP` | 通过 |
| AC-11 | TC-10 | 平台内建 SSO 的编辑弹窗仍按原 Nacos 配置打开。登录验密仍走 Nacos 里的 SSO，不使用接入服务上的直连 IP。用途、传输类型、启用状态仍不能改 | 通过 |
| AC-12 | TC-06 | 已有接入服务不编辑时仍按 Nacos 转发。表结构只在账号后端迁移，BFF 不对这套表做迁移 | 通过 |
