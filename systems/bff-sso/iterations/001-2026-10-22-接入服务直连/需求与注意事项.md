# 需求与注意事项：接入服务可选直连

当前进度只看 [status](./status.md)。要改哪些项目和文件见 [改动范围](./改动范围.md)。已经拍板的见 [决策记录](./决策记录.md)。验收见 [验收标准](./验收标准.md)，步骤见 [测试用例](./测试用例.md)。

## 背景

网关管理页「新增接入服务」里，Nacos 分组和服务名会参与转发。转发时向 Nacos 要健康机器，再连 `grpc://ip:端口`。没有「填 IP 直接连」的选项。

这次要在「子服务类型」和「Nacos 分组」之间加上接入类型。新建默认直接接入。Apifox 项目 ID 和状态仍留在表单下面，位置不动。

同一页上不能只改弹窗。页头说明、筛选、列表「发现方式」、连通测试弹窗里的「发现方式」和「Nacos 实例」现在都按 Nacos 展示，要按接入类型分开显示。逐条对照见 [改动范围](./改动范围.md) 的「页面上要改的位置」。

## 本次要做

### 页面（`adx-bff-frontend`）

改 `src/features/resources/ResourcePage.tsx` 的新增/编辑弹窗。这个弹窗是新增/编辑表单，要带 `validateTrigger={['onChange','onBlur']}` 和 `colon={false}`。有标签的必填项保留必填星。IP、端口、接入类型、Nacos 服务名都有标签。

接入类型两个选项：

| 选项 | 接口值 | 表单上显示 | 必填 |
|---|---|---|---|
| 直接接入 | `direct` | IP、gRPC 端口 | 都必填 |
| Nacos 接入 | `nacos` | 现有的 Nacos 分组、Nacos 服务名 | 服务名必填。分组可空 |

- 选直接接入：隐藏 Nacos 分组和服务名。隐藏后的项不再参与这次保存的校验。
- 选 Nacos 接入：隐藏 IP 和端口。隐藏后的项不再参与这次保存的校验。
- 点「新增接入服务」时，接入类型默认是直接接入。
- 点「编辑」时，按这条记录保存的 `accessType` 回显。库里已有记录迁移后是 `nacos`。
- 页面上 IP 和端口分成两个输入框。提交给接口时拼成一个 `directAddress`，格式是 `ip:端口`，中间没有空格。编辑时再拆开填回两个框。
- 页头说明、筛选、列表「发现方式」、连通测试弹窗，按 [改动范围](./改动范围.md) 里的页面位置表改。连通测试在直连时不查 Nacos 实例，探测填写的地址。弹窗里「发现方式」按记录显示「直接接入」或「Nacos 服务发现」。「Nacos 实例」整行只在 Nacos 接入时出现。

IP 只收 IPv4。每一段是 0 到 255 的整数。除了单独一个 `0`，段里不能有前导 0。下面这些都不能保存：

- 空 IP、空端口
- 主机名
- IPv6
- 已经带 `grpc://` 的整段地址
- 端口不是 1 到 65535 的整数，例如 `0`、`65536`、小数

### 保存与校验（`adx-bff-backend`）

创建、修改接入服务时带上 `accessType`。直连地址字段名是 `directAddress`。

- 直接接入：不要求 Nacos 服务名。`directAddress` 必须是合法 IPv4 加端口。保存时把 `nacosServiceName` 和 `nacosGroup` 写成数据库空值 `null`。空字符串仍会被订阅查询扫到，不能用空字符串代替 `null`。
- Nacos 接入：仍要求 Nacos 服务名。保存时把 `directAddress` 写成 `null`。分组沿用现在的规则：页面可以留空，后端空分组仍用代码里现有的默认分组去找实例。
- 更新接口现在是「没传的字段保持原值」。这次只要请求里带了 `accessType`，就要按这一种整组落库，主动清掉另一种字段。只改名称、状态、Apifox 时可以不带 `accessType`，原接入方式保持不动。
- 转发找地址只改 `NacosTargetResolver`。直接接入时把 `directAddress` 拼成 `grpc://ip:端口` 返回，不查 Nacos，也不读写那份 5 秒实例快照。失败不换另一台。Nacos 接入保持现在的选实例和换机。
- 这四个入口都要先看接入类型：`resolveGrpcBaseUrl`、`resolveGrpcTargets`、`resolveFailoverAttemptLimit`、`listSelectableNacosInstances`。直连地址缺失或解析失败时直接报错，不能改去走 Nacos。
- `/proxy`、业务平台授权转发、按接入服务找账号后端，都把 `accessType` 和 `directAddress` 传进这个解析器。授权转发和找账号后端现在会把接入服务行缓存 30 秒。这轮不另做缓存失效。改完类型后，这两条路最多再按旧数据走 30 秒。验密码不走这条记录。
- 连通测试同样走这条规则。直连的诊断摘要不出现「未发现 Nacos 实例」。
- 列表返回给页面的查询要选出 `accessType` 和 `directAddress`，否则编辑无法回显。

### 数据

接入服务表 `sys_sub_service` 增加：

| 页面和接口上的名字 | 库里的类型和列 | 取值 |
|---|---|---|
| `accessType` | 枚举 `SubServiceAccessType`，列 `access_type` | `direct` 或 `nacos`。已有行默认 `nacos` |
| `directAddress` | 可空字符串，列 `direct_address`，`VarChar(32)` | 存 `ip:端口`。已有行默认空 |

表结构只在 `adx-admin-backend` 做迁移。BFF 的 Prisma 模型和注释清单要同步这两个字段，但不要在 BFF 里对这套表执行迁移。

## 默认与老数据

| 场景 | 接入类型 |
|---|---|
| 新增接入服务 | `direct`。表单显示 IP 和端口 |
| 现在库里已有的服务 | 迁移后是 `nacos`，`directAddress` 为空。编辑时回显 Nacos 分组和服务名 |
| 改成另一种之后再保存 | 只保留当前这种的字段。另一种写成 `null` |
| 编辑时只改名称、状态、Apifox，请求不带 `accessType` | 接入类型和地址字段保持原样 |

平台内建 SSO 那一行如果原来是 Nacos，编辑打开时仍是 Nacos。不要因为新建默认直连，就把内建 SSO 改掉。它现有的三道限制还在：不能改服务用途、传输类型、启用状态。接入类型和地址可以按上面的规则保存。

## 不做

- 不改 BFF 自己找 SSO 验密码的方式。验密码仍用 Nacos 配置里的 SSO 服务，不读这条接入记录上的 IP。
- 直连只支持一个 IPv4 地址，不做多 IP 轮询，也不收主机名和 IPv6。要多台机器仍选 Nacos 接入。
- 不把页面上的 `MERGEX_GROUP` 和后端找实例用的 `MERGEX_FRONTEND_CONFIG_GROUP` 合成一个。空分组的 Nacos 老行为保持原样。
- 不改 Proto 导入。接口文档还是用现在的 Proto 地址，不从 Nacos 的 HTTP 端口去拉。
- 不移动 Apifox 项目 ID、状态，也不改子服务类型、绑定环境的规则。
- 不在这次改账号管理页。
- 不改 `adx-sso-backend` 的 Prisma 模型。那边的 `SubService` 还是旧字段，和账号后端不是同一份模型。

## 注意事项

- 五个项目里，这次会动到 `adx-bff-frontend`、`adx-bff-backend`、`adx-admin-backend`。SSO 和账号管理页不动。
- 直连地址不要写进代码常量，放在这条接入服务的记录里。
- Nacos 订阅列表只订阅 Nacos 接入、并且 `nacosServiceName` 去掉空白后仍有内容的记录。直接接入必须把服务名写成 `null`。
- 配置示例里的数据库密码、令牌不要写进迭代文档。文档里的 IP 只用文档示例地址，例如 `192.0.2.10`。
