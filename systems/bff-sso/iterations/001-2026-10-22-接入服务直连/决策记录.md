# 决策记录

| 编号 | 决定 | 原因 | 没采用的做法 |
|---|---|---|---|
| D-01 | 接入类型放在「子服务类型」下面、「Nacos 分组」上面 | 和页面上圈定的位置一致 | 放在表单最底下，或替换掉 Apifox |
| D-02 | 新建默认「直接接入」 | 按本次要求，新服务先填 IP | 新建默认 Nacos |
| D-03 | 已有服务编辑时按原记录回显，现在库里的都视为 Nacos | 避免一打开编辑就把原来的服务名清掉 | 编辑也默认改成直连 |
| D-04 | 直连只保存一个 `ip:端口`，转发时拼成 `grpc://ip:端口`，失败不换机器 | 直连没有实例列表 | 直连也做多 IP 轮询 |
| D-05 | 选中一种就清掉另一种的字段，清掉的值写成 `null` | 订阅查询认的是「不是 null」。空字符串仍会被扫到 | 两种字段同时保留，或写成空字符串 |
| D-06 | 找地址只改 `NacosTargetResolver` 的四个入口 | `/proxy`、授权转发、按接入服务找账号后端、连通测试都走这里 | 每个调用方各写一套直连 |
| D-07 | 登录验密码仍走 Nacos 配置里的 SSO，不读接入服务上的 IP | 验密和「接入服务」不是同一条路 | 把 SSO 登录也改成读这条记录的 IP |
| D-08 | 表结构只在账号后端迁移 | 三个后端里，迁移入口只有账号后端。SSO 的 Prisma 模型已经是另一套旧字段 | 在 BFF 或 SSO 里执行迁移，或顺手把 SSO 模型改成和账号后端一样 |
| D-09 | 直连只收 IPv4。每段 0 到 255，除了单独的 `0` 不能有前导 0。端口是 1 到 65535 的整数 | 页面是 IP 和端口两个框，主机名和 IPv6 会让拼地址和校验变复杂 | 允许主机名、IPv6，或允许用户直接粘贴 `grpc://` |
| D-10 | 字段名用 `accessType` 和 `directAddress`。枚举类型叫 `SubServiceAccessType`，取值 `direct` / `nacos`。`directAddress` 是可空的 `ip:端口` | 和现有的 `SubServiceUsage`、`serviceUsage` 这种「类型名加字段名」一致。页面两个输入框只在提交前拼接 | 等代码写完再起名字，或把 IP、端口拆成两列 |
| D-11 | 这轮不合并两套默认分组。页面空分组仍按 `MERGEX_GROUP` 展示和筛选；后端找 Nacos 实例时，空分组仍用 `MERGEX_FRONTEND_CONFIG_GROUP` | 这是现存行为。这次只让直连行在选了某个分组时不要被算进去 | 把页面和后端改成同一个默认分组 |
