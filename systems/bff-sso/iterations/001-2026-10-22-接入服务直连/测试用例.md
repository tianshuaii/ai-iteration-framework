# 测试用例：接入服务可选直连

需求见 [需求与注意事项](./需求与注意事项.md)，勾选结果见 [验收标准](./验收标准.md)。

前置：用超管打开网关管理页的「接入服务」。BFF、账号后端已启动，且已有至少一条改前就存在的 Nacos 接入服务。文档和输入示例用 `192.0.2.10` 这类测试网段，不写真实机器地址。

授权转发和「按接入服务找账号后端」有 30 秒缓存。测这两条是否改用新地址时，保存后等缓存过去再发请求。`/proxy` 不走这个缓存。

## TC-01 新增默认直接接入

1. 点击「新增接入服务」。
2. 看「子服务类型」和下面的字段，再看 Apifox、状态的位置。
3. 看必填项的星，以及输入后离开输入框会不会提示。

期望：

- 接入类型在子服务类型下面。
- 默认选中「直接接入」。
- 能看到 IP、gRPC 端口。
- 看不到 Nacos 分组、Nacos 服务名。
- Apifox 项目 ID 和状态仍在这些字段下面。
- 有标签的必填项能看到星。IP 或端口不合法时，离开输入框就会提示。

## TC-02 切换到 Nacos 接入

1. 在新增弹窗把接入类型改成「Nacos 接入」。
2. 不填 Nacos 服务名，点保存。

期望：

- Nacos 分组和服务名出现，IP 和端口消失。
- 保存被拦住，提示要填 Nacos 服务名。
- 分组可以留空。留空时仍按现在的规则保存，不在这轮改成另一个默认分组。

## TC-03 直接接入校验

接入类型保持「直接接入」，分别尝试保存：

1. IP 空着，端口填 `50051`。
2. IP 填 `192.0.2.10`，端口空着。
3. 端口填 `0`、`65536` 和 `1.5`。
4. IP 填主机名 `example.com`。
5. IP 填 IPv6 `2001:db8::1`。
6. IP 填 `grpc://192.0.2.10:50051`。
7. IP 填 `192.0.2.256` 和 `192.168.001.1`。

期望：这些都不能保存，提示缺 IP、缺端口或地址不合法。不产生新的接入服务。

## TC-04 直接接入保存与回显

1. 接入类型选直接接入。
2. IP 填 `192.0.2.10`，端口填 `50051`，其余必填项按页面要求填完，保存。
3. 在列表查看发现方式。
4. 再点编辑。

期望：

- 保存成功。
- 列表显示直接接入，以及 `192.0.2.10` 和 `50051`。
- 编辑时仍是直接接入，IP 和端口还在。
- 这条记录的 `directAddress` 是 `192.0.2.10:50051`。
- `nacosServiceName` 和 `nacosGroup` 是 null，不是空字符串。Nacos 订阅里也没有它。

## TC-05 Nacos 接入保存与回显

1. 新增一条，接入类型选 Nacos 接入。
2. 填写分组和服务名后保存。
3. 再编辑。

期望：

- 列表显示 Nacos，以及分组和服务名。
- 编辑时仍是 Nacos 接入，分组和服务名还在。
- `directAddress` 是 null。看不到 IP、端口输入框。

## TC-06 老数据编辑不丢 Nacos

1. 打开一条本次改动之前就存在的接入服务。
2. 看接入类型和 Nacos 字段。
3. 直接关闭，不保存。
4. 再用这条服务做一次原来能成功的转发。

期望：

- 打开时是 Nacos 接入，原来的分组和服务名都在。
- 关闭后列表不变。
- 转发仍然按 Nacos 找实例，不要求填写 IP。
- 没改过的老行 `accessType` 是 `nacos`，`directAddress` 是 null。

## TC-07 从 Nacos 改成直连后的转发

1. 准备一条 Nacos 接入，并确认现在 `/proxy` 转发会向 Nacos 要地址。
2. 编辑它，改成直接接入，填 `192.0.2.10` 和 `50051`，保存。
3. 再对该服务发一次 `/proxy` 转发。

期望：

- 转发目标是 `grpc://192.0.2.10:50051`。
- 这次转发不再查询该服务的 Nacos 服务名。
- 若改测授权转发或找账号后端，先等 30 秒缓存过去。

## TC-08 失败时换不换地址

1. Nacos 接入且 Nacos 里有两台健康实例时，让第一次连上的那台拒绝连接，再转发。
2. 直接接入只填一个地址，让这个地址拒绝连接，再转发。

期望：

- Nacos 接入会再试另一台。
- 直接接入只试填写的那一个地址，不会改去连别的 IP。

## TC-09 连通测试弹窗

1. 对一条直接接入点「连通测试」。
2. 看「发现方式」「gRPC 探测」，以及有没有「Nacos 实例」。
3. 再对一条 Nacos 接入点「连通测试」，看同样几行。

期望：

- 直接接入的「发现方式」是「直接接入」，不是「Nacos 服务发现」。
- 没有「Nacos 实例」这一行，能看到所填 IP 和端口。gRPC 探测地址是这个地址。诊断摘要不写「未发现 Nacos 实例」。
- Nacos 接入的「发现方式」是「Nacos 服务发现」，「Nacos 实例」仍有分组、服务名、健康实例数和 `grpc://` 地址。
- 运行包、检测时间两种都还在。

## TC-11 列表说明、发现方式列和筛选

1. 看接入服务页标题下的说明。
2. 看列表「发现方式」列：一条直连、一条 Nacos。
3. 筛选里接入类型选「直接接入」，再选「Nacos 接入」。
4. 接入类型清空，Nacos 分组选一个具体分组。
5. 再看一条分组为空的老 Nacos 服务，用分组筛选里的 `MERGEX_GROUP` 去筛。

期望：

- 页头说明同时提到直接接入和 Nacos。
- 直连行显示 IP 和端口；Nacos 行显示分组和服务名。
- 按接入类型筛选时，只留下对应的行。
- 选了某个 Nacos 分组后，直连行不在结果里。
- 分组为空的 Nacos 行，筛选行为仍和改前一样，按 `MERGEX_GROUP` 比较。这轮不把它改成 `MERGEX_FRONTEND_CONFIG_GROUP`。

## TC-10 不改登录验密

1. 打开平台内建 SSO 的编辑弹窗。
2. 看接入类型、用途、传输类型、启用状态。
3. 不保存，关闭。
4. 用管理页重新登录。

期望：

- SSO 这条打开时仍是原来的 Nacos 配置。
- 用途、传输类型、启用状态仍然不能改。
- 登录验密成功与否只取决于 Nacos 里的 SSO，不受别的接入服务是否填了直连 IP 影响。
