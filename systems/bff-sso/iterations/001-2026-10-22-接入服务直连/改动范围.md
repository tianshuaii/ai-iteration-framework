# 改动范围

这轮属于 bff-sso。仓库绝对路径写在 `ai-iteration-framework/systems/bff-sso/overview.md`，按那个路径打开原来的仓库。本文件是这一轮允许改动的全部范围。

## 要改的项目

| 项目 | 这一轮它负责什么 |
|---|---|
| `adx-bff-frontend` | 新增/编辑弹窗的接入类型、列表上的发现方式、筛选、连通测试文案 |
| `adx-bff-backend` | 保存校验、按类型找 `grpc://` 地址、连通测试、Prisma 模型同步、列表把新字段返回给页面 |
| `adx-admin-backend` | 接入服务表增加 `accessType` 和 `directAddress`，并只在这里做迁移 |

## 页面上要改的位置

都在网关管理页「接入服务」。用户圈出的是新增弹窗；同一页上还有多处把发现方式写成 Nacos，这次一起改。

| 位置 | 现在 | 改完 |
|---|---|---|
| 页头说明 | 「维护 BFF 精确转发目标（Nacos 服务发现）」 | 写明可以是直接接入，也可以是 Nacos |
| 筛选「Nacos 分组」 | 没有分组的行会被当成 `MERGEX_GROUP` | 增加「接入类型」筛选。选了某个 Nacos 分组时，先去掉 `accessType = direct` 的行，直连不出现。Nacos 行的空分组仍按 `MERGEX_GROUP` 参与筛选。后端找实例用的 `MERGEX_FRONTEND_CONFIG_GROUP` 不动 |
| 列表「发现方式」列 | 永远是蓝色「Nacos」，下面是分组和服务名 | 直连显示 IP 和端口；Nacos 仍显示分组和服务名 |
| 新增/编辑弹窗 | 「子服务类型」下面直接是 Nacos 分组、Nacos 服务名，服务名必填 | 中间插入接入类型。新建默认直接接入。直连只显示 IP 和端口；Nacos 才显示分组和服务名。表单使用 `validateTrigger={['onChange','onBlur']}` 和 `colon={false}`。Apifox、状态不动 |
| 连通测试弹窗「发现方式」 | 写死「Nacos 服务发现」 | 按这条记录显示「直接接入」或「Nacos 服务发现」 |
| 连通测试弹窗「Nacos 实例」 | 总有这一行：分组 / 服务名、健康实例数、每个 `grpc://` 地址 | 只有 Nacos 接入才有。直接接入改成显示所填 IP 和端口，不出现实例列表和 weight |
| 连通测试里的 gRPC 探测、运行包、检测时间、诊断摘要 | 探测地址来自 Nacos 选中的实例 | 这些行保留。直连时探测地址是所填地址；摘要不要出现「未发现 Nacos 实例」 |

## 大致文件

### adx-bff-frontend

- `src/features/resources/ResourcePage.tsx`：页头说明、筛选、列表「发现方式」、新增/编辑弹窗。提交时把 IP 和端口拼成 `directAddress`；编辑时拆开回显
- `src/lib/service-list-filter.util.ts`：增加接入类型条件。选了 Nacos 分组时排除 `direct`。空分组仍按现有的 `MERGEX_GROUP` 比较，不要改成后端那个默认值。该文件已有测试，要一起改
- `src/features/resources/ServiceConnectivityModal.tsx`：发现方式按记录显示；直连不渲染「Nacos 实例」
- `src/lib/admin-api.ts`：接入服务和连通测试结果的类型加上 `accessType`、`directAddress`。发现方式现在只有 `nacos`

- `src/admin/dto/admin.dto.ts`：创建、更新的校验。直连要合法的 IPv4 和端口；Nacos 仍要服务名。带了 `accessType` 的更新按整组处理

## 明确不动

| 项目 | 为什么不动 |
|---|---|
| `adx-sso-backend` | 验密码仍走 Nacos 配置，不读接入服务上的 IP。它的 `SubService` 模型是旧字段，这轮不去对齐 |
| `adx-admin-frontend` | 账号权限页没有接入服务表单 |

下面这些也不在范围内：Proto 导入、Apifox 字段的位置、子服务类型和绑定环境的规则、多 IP 轮询、主机名、IPv6、合并两套默认分组、在 BFF 或 SSO 里执行治理表迁移、给 30 秒行缓存加主动失效。
