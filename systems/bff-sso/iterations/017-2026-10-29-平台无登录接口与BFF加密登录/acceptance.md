# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | 创建平台时可不选登录接口，保存后列表显示“BFF 登录”且平台有效 | 未测 |
| AC-02 | TC-02 | 登录配置要么完整、要么全部为空；半套配置被前后端拦截 | 未测 |
| AC-03 | TC-03 | BFF 登录不传平台字段时，Admin/Portal 平台内建登录行为保持不变 | 未测 |
| AC-04 | TC-04 | BFF 登录传入无自有登录接口的平台后创建归属该平台的 Session | 未测 |
| AC-05 | TC-05 | 上述 Session 转发非白名单接口时只注入 `X-BFF-Secret`，不出现 `X-BFF-User-Id` | 未测 |
| AC-06 | TC-06 | 有自有登录接口的平台继续走上游登录接管，并同时注入密钥与平台用户 ID | 未测 |
| AC-07 | TC-07 | 浏览器登录请求和 BFF→SSO 登录 RPC 均不含明文密码，SSO 能正确解密并登录 | 未测 |
| AC-08 | TC-08 | 错误密文、未知/过期 `keyId`、过期时间戳和重复 nonce 均稳定拒绝且日志不泄露密码或私钥 | 未测 |
| AC-09 | TC-09 | 密钥轮换窗口内新旧密文按规则处理，窗口结束后旧密钥不可再登录 | 未测 |
| AC-10 | TC-10 | 既有平台数据、平台账号绑定、白名单与平台自有登录行为不回归 | 未测 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。

AC-04、AC-07～AC-09 的核心口径已由用户原话 `Q1-Q5 都按推荐做` 确认；具体加密信封、Redis 故障和公钥刷新验收步骤等待 Q6～Q8 确认。
