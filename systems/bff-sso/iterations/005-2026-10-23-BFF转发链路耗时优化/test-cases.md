# 测试用例

前置：使用可复现的 HTTP 直通接口和固定上游响应，保留白名单内外各一条原接口；记录 BFF 与上游版本、环境、负载及发现模式。服务启停、测试数据写入另行授权。所有当前结果均为未测。

## TC-01 分段定位

1. 对同一 HTTP 直通 GET 接口采集多次完整 Trace，区分首次请求与连续请求。
2. 对照 BFF 分段、上游处理时间、独立客户端耗时和日志采集状态；再检查 Nacos 与直连、带正文与不带正文场景。

期望：每段有明确起止边界和样本量；可指出耗时集中在哪一段。缺失事件的 Trace 被标记，不作为性能基线。

## TC-02 耗时口径与时间轴

1. 打开同一 Trace 的请求查询列表和详情；对照子请求计时、整条请求计时及事件时间戳。
2. 打开一条旧日志、一条完整的直通原始流日志，以及一条确实丢失事件的日志。

期望：两种耗时的名称和含义明确；时间轴不把非 body 阶段的空档说成读取请求体；旧日志可读，原始流本身不触发误报，真正不完整的日志说明不能归因。

## TC-03 优化前后对照

1. 按确认后的基线条件分别在优化前后采集相同请求。
2. 汇总 P50/P95、样本量、上游耗时、BFF 额外耗时与异常样本。

期望：预热后的 BFF 入站至发起上游请求前耗时 P95 ≤ 100 ms；同时报告优化前后 P50/P95、样本量和冷路径结果。无法满足时明确未通过并保留原始记录。

## TC-04 白名单直通与流式响应

1. 不带登录请求白名单内接口，并让上游分段输出响应。
2. 核对上游收到的方法、路径、查询和正文，以及客户端首段和结束时间。

期望：请求成功且按流传输；BFF 不额外设置转发超时或改变响应体。

## TC-05 非白名单与非法路径

1. 无登录、有效登录分别请求非白名单接口。
2. 请求运行包未包含的路径；再验证无生效包及重复生效包。

期望：原有拒绝与放行规则不变；被拒绝的请求没有到达上游。

## TC-06 单发和批量回归

1. 调用 `/proxy/one` 与 `/proxy/batch` 的成功、失败和超时场景。
2. 对照既有响应信封、逐项结果及登录要求。

期望：原契约不变。

## TC-07 日志采集故障隔离

1. 在可控测试环境中使日志采集写入失败或队列满，再调用直通接口。
2. 恢复采集后查询相关日志和状态。

期望：业务响应不受影响；日志缺口可见，且故障样本不进入性能基线。
