# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | 同一环境的 HTTP 直通请求能记录可解释的分段耗时；上游处理、BFF 前置处理与响应传输分开显示，不完整样本不得用于基线。 | 通过 |
| AC-02 | TC-02 | 同一个 Trace 的列表“子请求耗时”和详情“BFF 整条请求耗时”口径清楚，时间轴不会把两个事件之间的所有耗时断言为读请求体。 | 通过 |
| AC-03 | TC-03 | 同一测试环境、同一白名单 GET 接口、预热后，从 BFF HTTP 入站至发起上游请求前的耗时 P95 ≤ 100 ms；报告优化前后 P50/P95、样本量及冷路径实测值。 | 通过 |
| AC-04 | TC-04 | 白名单内的 HTTP 直通仍免登录、流式传输且不设转发超时；上游请求与响应内容保持原样。 | 通过 |
| AC-05 | TC-05 | 非白名单直通仍需登录；不存在的原接口及不唯一生效包仍被拒绝，不打到上游。 | 通过 |
| AC-06 | TC-06 | `/proxy/one`、`/proxy/batch` 的鉴权、转发、响应信封和超时语义保持原样。 | 通过 |
| AC-07 | TC-07 | 日志采集失败或丢弃时业务请求结果不变，日志显示缺口；采集的性能开销与业务链路耗时可区分。 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。
