# 决策记录

| 编号 | 决定 | 原因 | 没采用的做法 |
|---|---|---|---|
| D-01 | 唯一路径字段名是 `publicPath`，列名 `public_path`。它是 `/proxy/` 后面的那一段，不是协议名。 | 用户要的是一段对外路径。名字按内容起，避免再写成带 grpc 的配置名。 | 叫 `grpcPath`，或把整条 URL 存进库。 |
| D-02 | 全系统未删除的项目里，`publicPath` 不能重复。只允许一段：以字母或数字开头，后面是字母、数字、下划线、短横线，最长 64。`one` 和 `batch` 保留给现有转发。 | 新地址是 `/proxy/{这段}/后面的路径`。带斜杠或和 `one`、`batch` 重名，会把现有转发抢走。 | 允许任意字符串，包括斜杠；或只在同一个项目里唯一。 |
| D-03 | 新转发按「当前绑定环境里，哪一台接入服务正在生效带这个唯一路径的运行包」找地址。一台都没有就失败。两台或更多同时生效也失败，不挑一台。 | 唯一路径挂在接口项目上，地址仍在接入服务上。两台同时生效时猜一台会打错服务。 | 在接口项目上再存一个固定地址；或命中多台时用第一台。 |
| D-04 | 白名单单独成行，每行是接口项目、方法、路径。只允许该项目原接口。空名单表示新地址上的接口都要登录。 | 用户要求只能从原接口多选。一行一个接口，保存时可以整批核对，不会写出一半。 | 用一个 JSON 字段存；或允许手写方法和路径。 |
| D-05 | 类型、唯一路径和白名单在打包导入时抄进运行包。服务接口包读这份抄件。之后改接口项目，已导入的包不变。 | 用户要求运行时的查看展示白名单。线上正在用的包不能跟着编辑弹窗立刻变。 | 查看时回读接口项目的当前白名单。 |
| D-06 | 白名单里的原接口走新地址时不登录。不在名单里的仍要登录，规则和 `/proxy/one` 一样。gRPC 包和没有唯一路径的包不能走新地址。 | 用户要求被选中的接口不走鉴权，其余接口不能因此变成公开接口。 | 整条新地址都不登录；或白名单也作用到 `/proxy/one`。 |
| D-07 | 新地址的请求和响应按流转发，不设超时。`/proxy/one` 和 `/proxy/batch` 的超时不动。 | 用户要求适配流数据，并且这条接口不处理超时。把全局超时一起拿掉会改变现有转发。 | 给新地址一个很长的超时；或所有转发都不设超时。 |
| D-08 | 已有 HTTP 项目的唯一路径和白名单先为空，编辑别的字段仍可保存。没填唯一路径之前，新地址拒绝。新建 HTTP 则必填唯一路径。 | 用户同意已有项目先空着，下次再补。如果一编辑就强制补路径，改个描述也保存不了。 | 迁移时给旧项目生成路径；或旧项目每次保存都必须补上。 |
| D-09 | 白名单只在「接口白名单」页管理。菜单紧挨在「原接口文档」下面。新建和编辑弹窗都不出现这项。选项来自该项目默认分支的原接口。 | 用户要求添加时不能选白名单，并要单独一页，放在原接口文档下面。保存仍走原来的项目更新，不新开表。 | 继续放在编辑弹窗里；或按顶栏当前分支各存一份名单。 |
