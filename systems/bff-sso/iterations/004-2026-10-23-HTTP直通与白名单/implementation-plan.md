# 实现计划

数据先加列和白名单表，行为集中在保存、打包和一条新地址上。产品代码还没改。

## 做法

账号后端做迁移，BFF 只同步 Prisma 模型，不在 BFF 里生成迁移。

接口项目增加可空的 `public_path`。未删除且路径不为空时，全库唯一。这条唯一索引写在迁移 SQL 里，因为只约束还在用的行。已有项目留空。

白名单新表，一行是接口项目、方法、路径。同一项目里同一方法和路径只保留一行有效记录。空表表示这个项目没有免登录接口。

运行包上增加可空的接口类型和 `public_path`，再加一张运行包白名单表。旧包这两列是空，白名单表没有行。导入时从接口包抄过来，之后不回读接口项目。

保存集中在 `project.service.ts`。新建 HTTP 必须有合法 `publicPath`。gRPC 带了路径或白名单就拒绝，库里保持空。白名单每一项都必须是该项目当前原接口的方法和路径，有一条对不上就整次不写。编辑路径或白名单只改项目上的当前值。

导出接口包时，把类型、唯一路径和白名单放进现有 manifest。旧包没有这三项仍能导入，导入结果就是空。摘要要把这三项算进去，避免两份白名单不同的包被当成同一个。

直通不进 `proxy.controller.ts`。在 `src/proxy/` 新增入口，只接 `GET`、`POST`、`PUT`、`DELETE` 的 `/proxy/{publicPath}/后面的路径`。第一段是 `one` 或 `batch` 时不接，留给现在的转发。

找目标时只查当前绑定环境里正在生效、且抄有这个 `publicPath` 的运行包。本机部署仍按已有规则看测试环境的生效包。零台或两台及以上都拒绝。地址仍用现在的 HTTP 基址：直连拼 `http://` 加 `directAddress`，Nacos 只用 `httpPort`。方法和后面的路径必须对上该包的原接口。对得上且在该包抄下的白名单里，不查登录；否则复用现有代理会话规则。请求和响应用流接过去，不调用 `forward-timeout.util.ts`，也不读完整响应再返回。

页面放在保存和打包字段定下来之后。接口项目先做，服务接口包后做，因为两边都要改 `admin-api.ts`。

## 为什么这样切

路径和白名单的规则只写在 `project.service.ts`，页面不再算一遍。直通单独一条入口，是为了不把免登录挂到现有控制器的类级别守卫上，也避免把 `/proxy/one` 的超时拿掉。运行包看抄件，所以查看不用再去查接口项目。

## 怎样避开「不做」

- 不改 `proxy.controller.ts` 的 `/proxy/one` 和 `/proxy/batch`。
- 不改 `forward-timeout.util.ts`，直通自己不套超时。
- 不改接入服务页，不在接入服务上存路径或白名单。
- 不改 SSO，不改账号管理页，不在 BFF 执行迁移。
- 不回填已经导入的运行包。
- 白名单不能选改造或整合，保存时按原接口核对。
