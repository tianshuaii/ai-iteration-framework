# 测试策略

## 自动

| 项目 | 命令 | 要挡住的错误 |
|---|---|---|
| `adx-bff-backend` | `pnpm test -- src/interface-version/services/project.service.spec.ts` | 新建 HTTP 没有唯一路径仍能保存；路径重复或写成 `one` 仍能保存；gRPC 写入路径或白名单；白名单夹带原接口之外的项却只写进一部分 |
| `adx-bff-backend` | 直通测试，命令在实现时写到对应的 `*.spec.ts` | 白名单请求没登录却被拒绝；非白名单没登录却转发；两台生效包同时命中时仍挑了一台；这条请求被套上超时 |
| `adx-bff-backend` | 运行包查看的现有或新增测试 | 查看结果没有打包时的白名单，或改了项目之后旧包的白名单跟着变了 |

示例路径只用文档地址，不把真实内网地址写进测试名称或断言消息。

## 手工

按 [test-cases](./test-cases.md) 执行，结果写入 [test-log](./test-log.md)。

前置：网关管理页能打开接口项目和服务接口包。至少有一个 HTTP 接口项目已经导入过原接口，并且有一个接入服务可以导入运行包。

## 回归

不能被改坏的老路径：

- `POST /proxy/one` 和 `POST /proxy/batch` 仍要登录，请求体不变。
- 新建 gRPC 项目仍只处理 Proto 地址，不出现唯一路径。
- 已有运行包仍能查看、设为生效、导出。没有新字段的旧包类型显示 `-`，白名单显示空。
