# 测试用例

前置：网关管理页能登录。已有一个 HTTP 接口项目，默认分支上有原接口。另有一个接入服务，用来导入运行包。示例唯一路径用 `orders`，不要写真实内网地址。

## TC-01 新建 HTTP 要填唯一路径

1. 新建接口项目，类型保持 HTTP。
2. 先不填唯一路径，保存。
3. 再填一段没人用过的路径，例如 `orders`，并填原接口 Apifox 项目 ID，保存。

期望：

- 第一次保存失败，并标出唯一路径。
- 第二次保存成功。列表的唯一路径是 `orders`。

## TC-02 新建 gRPC 不收这两项

1. 新建 gRPC 项目，不填唯一路径和白名单。
2. 再用接口直接带上路径或白名单保存一次。

期望：

- 页面上没有这两项，项目能按现在的方式创建。
- 接口带了这两项时拒绝，库里仍是空。

## TC-03 非法或重复的路径

1. 再新建一个 HTTP 项目，唯一路径仍填 `orders`。
2. 另试 `one`、`batch`，以及带斜杠的 `a/b`。

期望：

- 四次都保存失败。
- 已有的 `orders` 项目不被改掉。

## TC-04 老的 HTTP 项目可以先不补

1. 打开一个这一轮之前就存在、路径还是空的 HTTP 项目。
2. 只改描述并保存。
3. 不登录，访问 `/proxy/` 加一个并不存在的路径。

期望：

- 描述能保存，唯一路径仍显示 `-`。
- 新转发地址拒绝，没有把请求打到后面的服务。

## TC-05 白名单只选自原接口

1. 打开「接口白名单」，选中 `orders` 项目。新建和编辑弹窗里没有白名单。
2. 勾选两条原接口保存。
3. 再用接口夹带一条该项目原接口里没有的方法或路径，保存。

期望：

- 选项里只有原接口，没有改造或整合。
- 第一次保存成功。
- 第二次整次失败，上一次选中的两条还在。

## TC-06 白名单直通且不超时

1. 把带 `orders` 和这两条白名单的包导入一个接入服务，并设为当前环境生效。
2. 不带登录，用白名单里的方法和路径访问 `/proxy/orders/...`。
3. 用一条会持续输出的接口看响应是不是边到边出。

期望：

- 不登录也能转到该接入服务，响应按流回来。
- 这条请求没有套用 `/proxy/one` 的超时。

## TC-07 非白名单仍要登录，对不上就拒绝

1. 用同一条生效包里、不在白名单中的原接口，不带登录访问新地址。
2. 带上有效登录再访问一次。
3. 再用一个该包原接口里没有的路径访问。

期望：

- 第一次要求登录，没有打到后面的服务。
- 第二次转发成功，同样不套超时。
- 第三次拒绝，没有打到后面的服务。

## TC-08 生效包必须正好一台

1. 取消该接入服务的生效包后，再访问白名单接口。
2. 让两台接入服务同时生效带 `orders` 的包，再访问一次。

期望：

- 两次都拒绝。
- 不会挑其中一台继续转发。

## TC-09 运行包展示的是打包时的那一份

1. 打开服务接口包列表，看刚导入的包。
2. 点查看。
3. 回到接口项目，改掉白名单或唯一路径，不要重新打包。
4. 再打开刚才那个运行包的查看。

期望：

- 列表接口类型是 HTTP。旧包没有记录时是 `-`。
- 查看里的白名单是导入时的那两条。
- 项目改完之后，这个已导入包的查看内容不变。

## TC-10 原来的转发还要登录

1. 不带登录调用 `POST /proxy/one`。
2. 带登录，按原来的请求体转发一条已有接口。

期望：

- 第一次要求登录。
- 第二次仍按原来的超时和返回格式工作。
