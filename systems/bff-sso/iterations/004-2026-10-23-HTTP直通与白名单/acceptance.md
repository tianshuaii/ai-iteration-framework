# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | 新建 HTTP 接口项目必须填写唯一路径；合法且不重复时能保存 | 通过 |
| AC-02 | TC-02 | 新建 gRPC 项目不写唯一路径和白名单；请求里带了这两项会被拒绝 | 通过 |
| AC-03 | TC-03 | 唯一路径与未删除项目重复、写成 `one` 或 `batch`、或含有斜杠时，保存失败 | 通过 |
| AC-04 | TC-04 | 已有 HTTP 项目可以不补唯一路径就保存名称；没补之前，新转发地址拒绝 | 通过 |
| AC-05 | TC-05 | 白名单只能多选该项目的原接口；夹带别的方法或路径时整次保存失败 | 通过 |
| AC-06 | TC-06 | 白名单中的原接口走 `/proxy/{唯一路径}/...` 时不登录，按流转发，并且不套超时 | 通过 |
| AC-07 | TC-07 | 不在白名单里的原接口走新地址时仍要登录；方法和路径对不上原接口时拒绝，不打到后面的服务 | 通过 |
| AC-08 | TC-08 | 没有生效包，或两台接入服务同时生效同一个唯一路径时，新地址拒绝，不挑一台 | 通过 |
| AC-09 | TC-09 | 服务接口包列表显示打包时的接口类型；查看显示打包时的白名单。之后改项目不会改变已导入的包 | 通过 |
| AC-10 | TC-10 | `POST /proxy/one` 仍要登录，超时规则不变 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。
