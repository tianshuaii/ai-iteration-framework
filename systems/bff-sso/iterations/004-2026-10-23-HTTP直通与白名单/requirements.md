# 需求与注意事项：HTTP 直通与白名单

范围见 [change-scope](./change-scope.md)。已经拍板的见 [decisions](./decisions.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

接口项目已经能区分 HTTP 和 gRPC。HTTP 项目用原接口 Apifox 项目 ID 把原始接口拉进工作区，再打包成某个接入服务的运行包。真正对外的转发仍是 `POST /proxy/one` 和 `POST /proxy/batch`：调用方在请求体里写服务编码、方法和路径，而且必须先登录。这条转发会套超时，也不按流把响应原样送回去。

接口项目上还没有一段对外路径，也没有「哪些原接口可以不登录就转发」的名单。服务接口包的列表和查看里，也看不出这份包是 HTTP 还是 gRPC，查看里看不到白名单。

## 本次要做

### 页面

接口项目的新建、编辑弹窗保持表单：`validateTrigger={['onChange','onBlur']}`、`colon={false}`。有标签的必填项保留必填星。

#### 接口项目

新建 HTTP 项目时，在原接口 Apifox 项目 ID 之外再加「唯一路径」。

| 接口类型 | 唯一路径 | 接口白名单 |
|---|---|---|
| HTTP | 新建必填。一段路径，全系统不能重复 | 可不选。只能从该项目已经导入的原接口里多选 |
| gRPC | 不出现这个框。保存时必须是空 | 不出现。保存时必须是空 |

- 唯一路径只允许一段：字母、数字、下划线、短横线，不能有斜杠，也不能是 `one` 或 `batch`。这两段已经被现在的转发地址占用。
- 编辑 HTTP 项目时可以改唯一路径。改完仍不能和别的项目重复。
- 白名单不在新建或编辑弹窗里选。菜单在「原接口文档」下面，叫「接口白名单」。
- 这一页用顶栏当前的接口项目。选项只来自该项目默认分支上的原接口，按方法和路径显示。改造接口、整合接口不能选。
- 还没有导入原接口时，页面提示先去导入。名单可以留空，表示都要登录。
- 列表增加「唯一路径」。没有时显示 `-`。
- 页头补一句：HTTP 项目要填唯一路径；白名单里的原接口可以不登录，从 `/proxy/这段路径/...` 直接转发。

#### 服务接口包

菜单仍是「服务接口包」，路径仍是 `/runtime-packages`。

- 列表增加「接口类型」。这份包打包时是 HTTP 就显示 HTTP，是 gRPC 就显示 gRPC。旧包没有这份记录时显示 `-`。
- 点「查看」打开的运行包接口清单里，增加「接口白名单」。列出打包时抄下来的方法和路径。没有就显示空，不要写成「全部放行」。
- 页头补一句：这里看到的类型和白名单是打包时的那一份。之后在接口项目里改了，要重新打包并设为生效才会变。

### 接口与保存

接口项目创建、修改带上 `publicPath`。白名单字段名是 `whitelist`，每一项是原接口的 `method` 和 `path`。

- 新建 HTTP：`publicPath` 去掉空白后必须还有内容，并且符合上面的一段路径规则。`interfaceKind` 仍是 `http`。
- gRPC：请求里如果带了非空 `publicPath` 或非空 `whitelist`，拒绝保存。库里这两项保持空。
- 创建之后仍不能改 `interfaceKind`。
- 白名单里每一项都必须是该项目当前原接口里真实存在的方法和路径。多出来的、或来自改造、整合的，整次保存拒绝，不写进一半。
- 白名单可以是空数组。空数组表示这条新转发地址上的接口都要登录。
- 编辑时改唯一路径或白名单，只改接口项目上的当前值。已经导入的运行包不跟着改。

新转发地址：

```http
GET|POST|PUT|DELETE /proxy/{publicPath}/{后面的路径}
```

- `{publicPath}` 对上某个已生效运行包里抄下来的唯一路径。后面的路径加上这次的方法，必须对上该包里的一条原接口。
- 只接受这四种方法。别的方法拒绝。
- 这条地址只服务 HTTP 包。gRPC 包，或包上没有唯一路径，都拒绝，不改去走原来的 `/proxy/one`。
- 找到唯一一台接入服务：它在当前绑定环境里，正在生效的包带有这个唯一路径。一台都没有，拒绝。两台或更多同时生效，也拒绝，不挑一台。
- 当前部署环境仍按已有规则理解：本机 `dev` 用测试环境的生效包，生产部署用生产环境的生效包。
- 这条原接口在该包的白名单里：不检查登录，把请求体按流转到该接入服务，并把响应按流送回。不套转发超时。
- 不在白名单里：仍要登录，登录规则和现在的 `/proxy/one` 一样，管理端和业务平台的会话都可以。通过后再按流转发，同样不套超时。
- 路径对不上该包的原接口：拒绝，不把请求打到后面的服务。

### 数据

治理表只在账号后端迁移。网关只同步模型，不新增迁移目录。

| 名字 | 落在哪 | 含义 |
|---|---|---|
| `publicPath` / `public_path` | 接口项目 | 对外那一段路径。HTTP 可空只针对已有项目；新建 HTTP 必填。gRPC 必须是空 |
| `whitelist` | 接口项目的白名单行 | 每行是项目、方法、路径。只允许原接口。空表示都要登录 |
| 运行包上的类型、唯一路径、白名单 | 导入运行包时从接口包抄下来 | 服务接口包列表和查看读这份，不回读接口项目的当前值 |

已软删项目上的唯一路径不占名额，新建可以用同一个路径。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 新建 HTTP | 唯一路径必填。白名单默认不选 |
| 新建 gRPC | 没有这两项，库里是空 |
| 已有 HTTP 项目 | 唯一路径和白名单都是空。可以只改名称或描述并保存。没填唯一路径之前，新转发地址拒绝 |
| 已有 gRPC 项目 | 保持空。不能补成 HTTP 的路径或白名单 |
| 已经在用的运行包 | 不回填。列表类型显示 `-`，查看里白名单为空。要看到新内容，必须重新打包、导入并设为生效 |

## 不做

- 不改 `POST /proxy/one` 和 `POST /proxy/batch` 的登录要求、请求体和超时。
- 不把白名单用到原来的转发地址上。原来的地址仍一律要登录。
- 白名单不能选改造接口或整合接口，也不能手写一条原接口里没有的路径。
- 不因为改了接口项目，就改写已经导入的运行包。
- 不做页面按钮级权限。白名单只决定这条新地址要不要登录。
- 不改接入服务页，不在接入服务上保存唯一路径或白名单。
- 不推送 Apifox，不改 SSO，不改账号管理页。

## 注意事项

- 文件列表见改动范围，这里不重复贴路径。
- 迁移只在账号后端执行。网关只同步模型。
- `one` 和 `batch` 不能当唯一路径，否则会和现在的转发地址撞车。
- 新地址不设超时，只限这一条。不要把原来转发的超时也拿掉。
- 文档和页面示例不要写真实内网地址、令牌或密码。
