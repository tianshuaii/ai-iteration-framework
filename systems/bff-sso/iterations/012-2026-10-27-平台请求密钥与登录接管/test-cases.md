# 测试用例

前置：需求和计划已审批；需要真实迁移、服务、Redis 或模拟上游时已取得单独授权。

## TC-01 平台请求密钥必填

1. 新建平台时不填、填空字符串，再填普通字符串。
2. 分别执行失焦和提交。

期望：空值前后端均拒绝；普通字符串可保存，字段带必填星且 `onChange/onBlur` 生效。

## TC-02 密钥不泄露与编辑

1. 查询平台列表和详情，打开编辑弹窗。
2. 留空保存并确认保持原密钥，再输入新值保存并确认完成替换。
3. 检查响应、日志、错误和 Session。

期望：任何位置不出现密钥明文；保持不会误清，替换后新请求立即使用新值。

## TC-03 登录接口唯一识别

1. 配置两个可能命中同一登录子服务和接口的平台。
2. 保存或请求该接口。

期望：只允许唯一有效平台保存该登录接口稳定键，不静默选择任意一条。

## TC-04 上游登录错误原样返回

1. 上游返回 HTTP 200、业务 `code != 200` 的 JSON。
2. 再返回非 2xx HTTP 状态与同类业务体。

期望：状态、内容类型和响应体保持上游值；没有绑定查询和 Session 写入。

## TC-05 普通直通不被登录解析影响

1. 调用非登录接口，返回 JSON、文本和流式/下载内容。

期望：仍按现有方式原样转发，不因查找 `code` 或 `data.userId` 全量缓冲。

## TC-06 成功响应结构校验

1. 上游分别返回有效 string/number `data.userId`、缺失 userId、空值、对象、非 JSON。

期望：非空 string 或有限 number 转成字符串匹配；无效成功响应不创建 Session，并返回 `50201`。

## TC-07 平台账号绑定与账号状态

1. 当前平台分别测试无绑定、绑定到启用账号、绑定到禁用/软删除账号。
2. 另一个平台建立相同 `platformAccountId`。

期望：只匹配当前平台；无有效绑定或 BFF 账号失效返回 `40401`“该账户不存在”，不跨平台串号；只有启用 BFF 账号创建 Session。

## TC-08 登录成功响应

1. 使用有效绑定完成上游登录。
2. 对照 API 路径 /api/portal/auth/login 的响应。

期望：返回 `{ code: 200, data: { accessToken, expiresIn, tokenType }, msg }` 同等结构，不包含原上游成功数据；Redis Session 是 Portal audience 并保存平台上下文。

## TC-09 非白名单身份头

1. 使用平台 Token 请求非白名单接口。
2. 客户端同时伪造两个同名请求头。

期望：上游收到当前平台最新密钥和 Session 平台账号 ID，客户端值被覆盖且大小写不造成绕过。

## TC-10 白名单不注入

1. 无 Session 请求普通白名单接口与平台登录接口。

期望：已配置的平台登录接口作为动态登录例外可访问；上游不收到 `X-BFF-Secret` 或 `X-BFF-User-Id`。

## TC-11 失效与轮换

1. 登录后轮换密钥，再禁用/软删除平台、绑定或 BFF 账号，并让 Session 过期。
2. 分别请求非白名单接口。

期望：轮换立即使用新密钥；其余失效场景在转发前拒绝，不发送旧身份头。

## TC-12 原登录和代理回归

1. 执行原 Portal/Admin 登录、续期、退出。
2. 执行白名单和普通非登录 HTTP 直通。

期望：原 Portal/Admin 登录继续服务现有非直通能力，其 Token 调用非白名单 HTTP 直通时明确拒绝；普通正文、查询参数、状态和内容类型不回归。

## 受控浅功能回归用例

## SR-01 平台登录与业务请求主路径

前置：一个带请求密钥的平台、有效绑定、模拟 HTTP 上游。

步骤：调用原平台登录 URL取得 BFF Token，再携带 Token 请求一个非白名单接口。

期望：登录上游先验证，BFF 建 Session；后续上游收到正确的两项可信头。

## SR-02 原登录与直通相邻回归

前置：不修改密码、账号、子服务或运行包。

步骤：调用原 BFF/Admin 登录和一个白名单、一个普通非登录直通接口。

期望：最终兼容决策覆盖的老路径正常；停止在 Auth/Session/HTTP 直通一层，不做全系统回归。
