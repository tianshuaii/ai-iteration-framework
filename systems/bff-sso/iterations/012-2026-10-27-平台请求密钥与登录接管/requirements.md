# 需求与注意事项：平台请求密钥与登录接管

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

第 011 轮已经建立接入平台、平台登录接口和“平台账号 ID → BFF 账号”的绑定，但平台登录接口仍只是治理配置，HTTP 直通拿到上游响应后会原样返回，Session 也不知道本次登录来自哪个平台。

本轮让 BFF 接管已配置平台的登录成功响应：上游仍负责验证原平台凭据，BFF 只在上游业务成功后把平台账号映射成 BFF 账号并创建 Portal Session。后续非白名单 HTTP 直通从 Session 取得平台上下文，向上游注入可信平台身份头。

截图只用于确认上游使用 `{ code, data, msg }` 结构和 `code=200` 成功语义；本轮以用户文字指定的 `{ code: 200, data: { userId } }` 为正式成功契约，不把截图中的字符串 `data` 当作新契约。

## 本次要做

### 页面

1. Admin“接入平台”新建/编辑表单增加“请求密钥”字段。
2. 新建平台时请求密钥为字符串必填；不得把真实密钥显示在列表、日志或错误信息里。
3. 编辑页不回显密钥明文；留空表示保持原密钥，输入新值表示替换。

### 接口与转发

1. 接入平台创建/更新 API 接收请求密钥；服务端仍校验平台名称、子服务、登录子服务和登录接口。
2. HTTP 直通匹配到某个平台配置的登录接口时，先按现有方法、查询、正文和目标地址正常转发，不在转发前创建 Session。
3. 上游响应体的 `code` 不等于数值 `200` 时，保持当前直通语义，原样返回上游 HTTP 状态、响应头和响应体，不创建 Session。
4. 上游响应体的 `code` 等于数值 `200` 时，读取 `data.userId`，按当前平台和该平台账号 ID 查找有效绑定及有效 BFF 账号。
5. 未找到绑定时返回“该账户不存在”；找到后复用现有 Portal 登录的 ForwardContext、Redis Session、有效期和统一登录响应，不再返回原上游成功响应。
6. 平台登录 Session 必须保存本次平台 ID 与平台账号 ID，后续请求不得仅凭 BFF 账号反推平台。
7. HTTP 直通的非白名单接口通过 Session 校验后，在发给原上游的请求头中注入 `X-BFF-Secret: <平台请求密钥>` 和 `X-BFF-User-Id: <平台账号 ID>`。
8. 白名单接口继续免登录，并且不注入上述两个身份头；已配置的平台登录接口作为独立动态登录例外免 BFF Session，但仍须属于当前生效 HTTP 包。
9. 平台、账号绑定、BFF 账号或 Session 上下文失效时，不得继续向上游发送伪造或过期身份头。

### 数据

1. `sys_access_platform` 增加平台请求密钥存储字段；治理表迁移只在 Admin 后端执行，BFF 只同步 Prisma 模型。
2. Session 记录增加可选的平台上下文，至少包含接入平台 ID 和平台账号 ID；不把平台请求密钥复制进 Redis Session，转发时按平台 ID 读取当前有效配置。
3. 平台账号 ID 继续按字符串保存和大小写敏感匹配；上游 `userId` 接受非空 string 或有限 number，统一转换为字符串后匹配。
4. 有效平台的“登录子服务 + 登录接口稳定键”必须唯一，创建或编辑冲突时直接拒绝。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 新建平台 | 请求密钥必填；空字符串不允许保存。其余平台字段沿用第 011 轮规则。 |
| 已有平台 | 不伪造默认密钥；保持可查询，但补录密钥前不能登录接管或发送平台身份头。 |
| 上游登录 `code != 200` | 不查绑定、不创建 Session，原样返回上游响应。 |
| 上游登录 `code == 200` | 校验 `data.userId`，查平台绑定和 BFF 账号，成功后返回 BFF Portal 登录响应。 |
| 非白名单直通 | 只接受平台登录生成的 Portal Session；校验 Session 后注入平台密钥与平台账号 ID，原 Portal/Admin Token 明确拒绝。 |
| 白名单直通 | 沿用免登录与原样转发，不注入平台身份头。 |

## 不做

- 不把平台请求密钥写死在代码、Nacos 或前端构建变量里。
- 不让浏览器自行提交或覆盖 `X-BFF-Secret`、`X-BFF-User-Id` 作为可信身份。
- 不修改 SSO 的账号密码校验、密码格式或改密流程。
- 不改变上游平台自己的登录入参和凭据校验逻辑。
- 不接管上游 `code != 200` 的错误码、文案和数据结构。
- 不把平台请求密钥返回到平台列表、绑定列表、Session 响应或审计详情。

## 注意事项

- 本轮同时涉及接口契约、数据库迁移、安全头、Session 身份和多个仓库，按 `strict` 执行双阶段访谈、双审批、统一代码审核和 T4 真实验收。
- HTTP 直通当前以流式方式直接写上游响应；登录成功分支需要有界解析 JSON，普通接口和上游失败分支不得因此退化为全量缓冲。
- 具体文件范围见 [change-scope](./change-scope.md)。
