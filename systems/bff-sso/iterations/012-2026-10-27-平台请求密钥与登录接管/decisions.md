# 决策记录

| 编号 | 决定 | 原因 | 没采用的做法 |
|---|---|---|---|
| D-01 | 上游平台继续负责原登录请求校验；BFF 只在上游返回 `code=200` 后接管账号映射与 Session 创建。 | 用户明确要求“正常转发”，成功后才走 BFF Session。 | BFF 在转发前自行验证平台账号。 |
| D-02 | 上游 `code != 200` 时响应原样返回，不创建 Session。 | 用户明确要求错误响应保持原样。 | 把所有上游错误统一改成 BFF 错误信封。 |
| D-03 | 登录成功通过当前平台下的 `platformAccountId` 查找 BFF 绑定，不做跨平台全局查找。 | 第 011 轮唯一性边界是“同一平台”，相同账号 ID 可存在于不同平台。 | 只用 `userId` 全局查绑定。 |
| D-04 | 非白名单上游身份头由 BFF 从可信 Session 和平台配置生成，不信任浏览器传入值。 | 防止调用方伪造平台密钥或平台账号身份。 | 直接转发客户端同名请求头。 |
| D-05 | 平台请求密钥不复制进 Redis Session；Session 只保存平台 ID 与平台账号 ID，转发时读取当前配置。 | 密钥轮换应立即生效，也避免扩大敏感值存储面。 | 登录时把密钥快照固化进 Session。 |
| D-06 | 有效平台的“登录子服务 + 登录接口稳定键”必须唯一，创建或编辑冲突时直接拒绝。 | 入站没有平台 ID，唯一约束可避免登录请求错误匹配平台。 | 请求时选第一条或允许调用方指定平台。 |
| D-07 | 请求密钥使用独立主密钥加密入库；新建非空必填，编辑留空保持、输入新值替换，API、列表和日志不返回明文。 | BFF 必须可取出密钥转发，同时控制静态存储和回显泄露风险。 | 明文保存、固定掩码覆盖或把密钥放入 Session。 |
| D-08 | 已配置的平台登录接口作为动态登录例外免 BFF Session，但仍要求接口属于当前生效 HTTP 包。 | 登录发生在 Session 创建之前，且不能扩大其他白名单范围。 | 要求预先登录或直接改写普通白名单。 |
| D-09 | `userId` 接受非空 string 或有限 number 并转字符串；结构非法返回 `50201`，无绑定或 BFF 账号失效返回 `40401`“该账户不存在”。 | 区分上游协议异常和账号不存在，并统一平台账号 ID 的匹配类型。 | 静默转发异常成功体或把所有问题都当未绑定。 |
| D-10 | 非白名单 HTTP 直通只接受平台登录生成的 Portal Session；原 Portal/Admin Token 调用该路径时明确拒绝。 | 旧 Session 没有平台上下文，无法安全生成平台密钥和账号头。 | 猜测平台、漏发身份头或信任浏览器补头。 |

## 确认依据

- D-06 至 D-10 对应 Q1-Q5，均由用户原话“`Q1-Q5 都按推荐做`”确认。
- 当前没有待确认事项。
