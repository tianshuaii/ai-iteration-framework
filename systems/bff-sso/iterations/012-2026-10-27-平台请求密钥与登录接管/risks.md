# 风险与回退

| 风险 | 影响 | 怎样避免 | 怎样退回 |
|---|---|---|---|
| 加密主密钥缺失、错误或多实例不一致。 | 无法读取平台密钥，错误实例可能持续拒绝请求。 | 启动期严格校验配置；使用带版本和认证标签的密文信封；解密失败时失败关闭且不记录敏感值。 | 恢复原主密钥配置并重启本轮服务；不以明文或代码兜底。 |
| 任意字符串经 trim、掩码或序列化后发生变化。 | 上游收到的密钥与管理员输入不一致。 | 仅拒绝真正的空字符串，新建保存和转发保持原字符；编辑空字符串单独解释为“不替换”。 | 用编辑接口重新写入正确密钥，旧密文不物理删除。 |
| 两个平台命中同一登录接口。 | 登录成功可能使用错误密钥并绑定到错误平台。 | 数据库对有效登录子服务和接口稳定键建立 partial unique，服务端预检并捕获并发冲突。 | 禁用或编辑冲突平台；回退代码前保留唯一约束，避免恢复歧义。 |
| 登录响应缓冲无上限或影响普通流式转发。 | 大响应导致内存峰值，下载和慢响应发生性能回归。 | 只对唯一平台登录接口启用有界缓冲；普通接口保持现有流式管道；超限在创建 Session 前失败。 | 关闭登录接管分支即可恢复全部原样流式转发。 |
| 上游业务失败在解析后被重组。 | HTTP 状态、响应头或原始字节变化，破坏现有客户端错误处理。 | 保存原始响应字节和上游头；只有业务 `code == 200` 才替换响应，其他情况原样写回。 | 回退响应接管服务，恢复当前全量透传。 |
| 旧 Session 被误判为平台 Session，或升级模型使所有旧用户退出。 | 可能漏发身份头、串平台，或造成无关登录回归。 | 平台字段保持可选且旧 Session 继续服务原能力；非白名单 HTTP 直通显式要求两项平台字段，不反推平台。 | 回退平台字段读取和额外 Guard；原 Session 数据仍可解析。 |
| 客户端用不同大小写伪造同名头。 | 上游可能同时收到伪造值和 BFF 值。 | 发送前按 HTTP 头大小写不敏感规则删除所有同名值，再写入唯一可信值；定向测试覆盖。 | 临时关闭平台非白名单直通，避免在修复前发送可疑身份。 |
| 平台、绑定或账号在登录后失效。 | 旧 Token 可能继续带有效密钥访问上游。 | 每次非白名单转发重新读取当前平台密钥并校验平台、绑定和 BFF 账号状态；密钥不缓存进 Session。 | 禁用平台可立即阻断；必要时清理对应 Session，需另行授权。 |
| 三个真实仓库仍保留第 011 轮未提交改动，且本轮会重叠文件。 | 错误回退或格式化可能覆盖上一轮成果。 | 将现有 dirty 全部视为接管前基线；实现守卫逐文件记录，只在本轮允许范围追加，不使用 reset/checkout。 | 发生无法区分的重叠时立即停止，由用户决定先提交第 011 轮或另建受控 worktree。 |

## 发布与迁移授权边界

- 实现阶段只创建代码、migration 文件和测试，不执行数据库迁移。
- 启动本地服务、使用测试库或 Redis、创建验收夹具、提交、推送、合并、拉取和部署均需分别取得明确授权。
- 上线前所有 BFF 实例必须配置相同的主密钥和登录响应上限；缺失配置不得用代码默认值绕过。
