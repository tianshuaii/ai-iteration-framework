# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01、TC-02 | 超管创建平台时必须提交非空请求密钥；密钥加密保存，列表和 API 不泄露明文，编辑留空保持、输入新值替换。 | 通过 |
| AC-02 | TC-03 | 一条平台登录请求只映射一个有效平台；歧义配置在保存或请求阶段被明确拒绝。 | 通过 |
| AC-03 | TC-04、TC-05 | 平台登录请求先正常转发；上游 `code != 200` 时 HTTP 状态、响应头和响应体原样返回且不创建 Session。 | 通过 |
| AC-04 | TC-06、TC-07 | 上游 `code=200` 且 `data.userId` 有效时，只在当前平台查有效绑定；未绑定返回“该账户不存在”，已绑定则为对应有效 BFF 账号创建 Portal Session。 | 通过 |
| AC-05 | TC-08 | 登录接管成功返回与 API 路径 /api/portal/auth/login 相同的 BFF 信封和 Token 数据，不再返回上游成功响应。 | 通过 |
| AC-06 | TC-09、TC-10 | 非白名单 HTTP 直通通过校验后，上游只收到 BFF 覆盖写入的 `X-BFF-Secret` 和 `X-BFF-User-Id`；白名单请求不注入。 | 通过 |
| AC-07 | TC-11 | 平台密钥轮换、平台/绑定/BFF 账号失效和 Session 失效不会继续发送旧身份头或创建新 Session。 | 通过 |
| AC-08 | TC-12、SR-01、SR-02 | 现有 BFF/Admin 登录、普通 HTTP 流式直通、查询参数/正文/内容类型、白名单和审计链路按最终兼容决策不回归。 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。
