# 风险与回退

| 风险 | 影响 | 怎样避免 | 怎样退回 |
|---|---|---|---|
| 保留集计算错误或迁移期间数据漂移 | active/previous 包或有效项目历史被误删。 | T-01 用数据库关系计算保留集并 `RAISE EXCEPTION`；Q9 窗口内停止五项本机服务写入；迁移前后生成行数与关系清单。 | 立即停止后续步骤，用 Q7 已验证逻辑备份恢复目标 Schema；不尝试猜测性补数据。 |
| 外键、共享 Blob 或未知依赖阻断删除 | 迁移半途失败或误删仍被有效对象共享的数据。 | T-01 显式按依赖顺序处理，删除 Blob 前反向确认零引用；禁止隐式 `CASCADE`。 | 事务失败则不继续；若迁移已提交且后置核验失败，按演练流程恢复备份。 |
| 三后端 Prisma 模型不同步 | 运行时出现缺列、缺表或生成失败。 | T-02/T-03 只按 T-01 最终 Schema 同步，三个仓库都执行 Prisma generate 和定向测试。 | 先停止受影响服务，修正模型并重新生成；未获得新迁移授权不改数据库。 |
| 历史 migration 链异常 | `prisma migrate deploy` 被旧记录或缺失迁移阻断。 | 迁移前只读检查 `_prisma_migrations`、`flyway_schema_history` 和 Admin README 规定链路；不在 BFF/SSO 执行 deploy。 | 停止并记录失败；仅在用户确认后按 Admin 仓 README 的 Prisma resolve 流程处置。 |
| 009 未提交成果被覆盖 | 账户精简与密码逻辑丢失或混入本轮改动。 | 实施前逐文件记录 dirty 基线；只改任务声明文件；统一 review 排除接管前差异。 | 不使用 reset/checkout 覆盖基线；从 git diff 与记录中分离本轮新增差异。 |
| 备份文件不可用或含敏感数据 | 无法恢复，或测试库数据泄露。 | Q7 要求 SHA-256 和独立恢复演练；备份只保存于受控本机临时位置，文档只记录路径类别和校验结果，不记录连接串/密码。 | 演练失败即不迁移；删除失败备份，重新生成并再次演练。 |

## 回退原则

- 本轮数据库操作为前向迁移；物理删除和 DDL 没有可靠的通用 down SQL。
- `adx-admin-backend` 是唯一可部署迁移的仓库；BFF/SSO 只回退其模型代码，不回退共享数据库。
- 恢复仅能在用户再次授权后执行，使用通过 Q7 演练的备份，不触碰生产库。
- 若未获得独立迁移授权，T-05 保持未执行，迭代不得把 AC-01 至 AC-08 标为通过。
