# 线上测试库备份、恢复与迁移操作清单

> 状态：待单独外部写入授权。本文件只描述步骤，不执行命令。

## 固定边界

- 目标仅为线上测试 `public_management`，不得连接生产库或其他 Schema。
- 迁移文件为 Admin 的 `20261027090000_public_management_schema_slim`；BFF 与 SSO 不执行迁移。
- 窗口内停止五项本机服务的写入后再操作；当前实现阶段没有启动、停止或重启任何服务。
- 迁移元数据、`sys_audit_log` 以及活跃接口项目全历史必须保留。

## 执行前

1. 在授权窗口中导出仅含 `public_management` 的 Schema 与数据备份，并记录备份文件 SHA-256。
2. 导出迁移前表清单、行数、`yn=0` 清单、有效服务/项目清单和 active/previous 运行包清单。
3. 新建隔离恢复数据库，把备份恢复进去；核验 SHA-256、表清单与抽样行数一致。
4. 在恢复库执行迁移并记录 Prisma 迁移版本、开始/结束时间和全部 SQL 输出。

## 迁移后核验

1. 确认 `_prisma_migrations`、`flyway_schema_history`、`sys_audit_log` 仍存在。
2. 确认废弃表、`sys_sub_service.service_kind` 和不被保留的运行包均不存在。
3. 确认除 `sys_audit_log` 外没有任何 `yn=0` 行；审计表按 D-08 原样保留。
4. 确认每个活跃服务/环境只剩 active 与 previous 运行包，且四个有效接口项目仍完整可读。
5. 通过后才对线上测试目标执行同一迁移，并按 AC/TC 清单做定向回归。

## 失败处理

- 任一前置、外键、清单或回归核验失败：停止窗口，不在目标库继续试删。
- 使用已核验备份恢复到隔离库复现；迁移是前向清理，不提供伪造的 down SQL。
- 未经新的授权，不执行备份恢复、更改服务状态或再次部署迁移。
