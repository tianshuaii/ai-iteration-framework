# 风险与回退

| 风险 | 影响 | 怎样避免 | 怎样退回 |
|---|---|---|---|
| 48 字符随机盐 MD5 弱于 Argon2。 | 全部账号密码抗离线破解能力下降。 | 按已批准决策显式记录安全降级；盐用 Node `crypto`；密码至少 8 位；禁止日志泄露；用 golden vectors 锁定格式。 | 需要重新改回强哈希时另开迁移轮次；本轮不保留双格式兼容。 |
| Java 参考算法与两个 Node 实现细节不一致。 | Seed 创建的账号可能无法由 SSO 登录。 | SSO 与 Admin bootstrap 使用相同固定密码/盐 golden vectors，覆盖交织位置、长度和校验失败。 | 在迁移执行前回退代码；若已写入错误哈希，用一次性超管恢复和管理员重设修复。 |
| 旧 Argon2 密码全部失效且首个超管无法恢复。 | 所有人被锁在系统外。 | 上线前验证一次性恢复命令；密码只从环境变量读取；先恢复并验证超级管理员，再开放页面。 | 使用数据库备份恢复旧哈希并回滚应用；不得写入公共默认密码。 |
| 并发禁用/删除绕过“至少一个启用超管”。 | 管理端失去可用管理员。 | 在同一数据库事务中锁定相关超级管理员行，再校验数量并写入；补并发测试。 | 用一次性恢复入口重新启用超管；若迁移已执行，不依赖角色表恢复。 |
| 用户名历史重复值阻断唯一约束。 | 迁移失败或错误合并身份。 | 迁移前预检全部 `yn` 状态的用户名；发现重复立即停止，由用户另行决定数据治理，不自动改名。 | 迁移未执行时无需回退；执行中失败按事务回滚并保留预检报告。 |
| 物理删表和删列不可由普通应用回滚恢复。 | 角色、租户、路由、权限与授权历史不可在线恢复。 | 执行前必须有可恢复备份/快照标识；SQL 按依赖顺序删除；核对保留/删除白名单；实施阶段不执行迁移。 | 迁移后只能恢复数据库备份并协调回滚五个应用，不能伪造 down migration。 |
| Portal 仍有租户/角色/路由/权限目录调用。 | 删除表后旧调用报错，业务下拉或页面初始化失败。 | 按 Q14 明确保留的账户目录和要删除/置空的接口；BFF 与 Admin 同步切换并补契约测试。 | 迁移前回滚代码；迁移后恢复备份和旧服务，或保持新空合约继续运行。 |
| 多仓 proto、Prisma 与生成 SDK 不同步。 | 编译失败、RPC `UNIMPLEMENTED` 或字段解析错误。 | 先定最终 proto；BFF 映射、Admin 前端 SDK 和三个 Prisma 模型按任务依赖同步；逐仓构建后再联调。 | 在迁移前按仓库回滚；迁移后必须按协调发布顺序整体回滚。 |
| 旧 Redis Session 仍携带租户/角色授权上下文。 | 删表后旧会话继续放权或刷新失败。 | 按 Q16 让旧身份模型 Session 硬失效；日常账号变更继续按账号吊销；补遗留 Session 测试。 | 回退应用时恢复旧 Session 解释只会扩大风险，因此默认要求用户重新登录。 |
| 治理审计删除误伤 BFF 运行日志。 | 登录、退出、代理或请求查询失去审计证据。 | 明确保留 `sys_audit_log` 与 BFF 日志写入，只删除治理查询面和无意义治理 action；审核迁移保留表清单。 | 迁移前回退代码；表被误删时从备份恢复 `sys_audit_log`。 |
| `adx-bff-backend` 有接管前 dirty。 | 本轮误覆盖 HTTP 直通优化或把用户文件纳入成果。 | 实施前逐文件记录 dirty；任务范围排除 `src/proxy/http-passthrough.service*` 和 `CODE_REVIEW.md`；每次审核按精确路径核对。 | 停止当前任务并保留原修改；不使用 reset/checkout 覆盖用户内容。 |
| 发布时新旧服务交叉运行。 | 旧 BFF 调已删除 RPC，或新服务读取已删除列/表。 | 按 Q17 在维护窗口依次部署后端、执行迁移、部署前端，并逐步健康检查。 | 迁移前按相反顺序回滚；迁移后先恢复数据库备份，再整体回滚应用。 |
| 返工追加任务使计划摘要变化，旧能力证据不再满足当前门禁。 | 已完成代码被误判为无需复核，或为了恢复摘要而删除失败历史。 | 保留 T-01 至 T-11 完成状态和全部失败记录；重新审批后执行当前摘要范围守卫、统一 code review 与受影响定向检查，生成新能力证据。 | 守卫或审核发现产品漂移时停止并追加唯一返工任务，不伪造旧摘要或删除历史。 |
| BFF 两仓范围外全量基线被误纳入本轮。 | 接口编辑、外部 fixture 或环境配置修复导致范围膨胀，掩盖账户单一化验收。 | 按 Q22 只保留可复核失败证据；本轮关联定向检查单独通过，是否豁免由用户明确确认。 | 用户不接受豁免时保持 verify blocked，另开迭代修复，不在本轮顺手改。 |
| 浅功能回归扩大成全系统回归。 | 验收时间和风险失控，且难以区分本轮与历史失败。 | SR-01 只覆盖账户/密码/Session/门禁，SR-02 只覆盖普通代理、接口编辑、请求查询和实时日志；遵守各自停止边界。 | 出现边界外问题只记录并停止扩展；需求确需变化时退回 specify 重新审批。 |
| 迁移在删除主体表前未先删除账户外键。 | PostgreSQL 拒绝删除 `sys_tenant`，维护窗口内迁移中断。 | T-12 只把账户外键/索引删除提前到主体表删除之前；禁止用 `CASCADE` 隐藏遗漏，并在专用数据库执行单事务迁移与备份恢复复验。 | 失败时事务回滚；迁移成功后需要回退则恢复已验证的迁移前备份。 |
| 本人改密只调用 SSO，未吊销 BFF 旧 Session。 | 攻击者持有的旧 Session 在密码已更换后仍可继续访问，违背 TC-08。 | T-13 在 Portal/Admin 受保护认证入口中只信任当前 Session 身份，先按账户吊销全部 Session，再调用 SSO 改密；测试调用顺序、身份不可伪造和两类通道。 | 修复未发布前保持现有代码；若吊销成功但 SSO 失败，密码不变、Session 已失效，用户重新登录后重试，不恢复旧 Session。 |
| 通过中文错误消息判断 Admin 身份拒绝。 | Admin 文案变化会把正常权限拒绝误报为 `50001`，前端提示和监控失真。 | T-14 只依据结构化 gRPC `PERMISSION_DENIED` 转换 `40302`，并用未知错误传播测试防止过宽映射。 | 修复异常时回退 T-14 的局部改动；权限边界仍由 Admin 后端保持，不放宽管理端访问。 |

## 发布与迁移授权边界

- 实现阶段只写代码、迁移文件和测试，不执行数据库迁移。
- 启动本地服务、操作测试库、部署、提交、推送和生产备份均需分别获得明确授权。
- 正式迁移前必须记录环境、备份标识、操作者、开始时间和回滚负责人；没有这些信息不得执行。
