# 测试用例

前置：使用隔离测试账户与测试库；禁止把真实密码、哈希、盐或密钥写入测试记录。数据库迁移执行需另行授权。

## TC-01 Admin 只显示账户

1. 使用允许进入 Admin 的账户登录。
2. 检查侧栏、默认跳转和账户页面。

期望：只显示账户入口，默认进入账户列表。

## TC-02 已删除页面不可访问

逐一访问旧的概览、租户、角色、关系、路由、权限、授权和治理审计地址。

期望：旧页面不渲染，并按最终路由约定返回账户页或 404。

## TC-03 账户正常操作

核对列表列与三类筛选；执行新增、编辑、启停、独立重设密码和软删除测试夹具；创建第二个超级管理员。

期望：列表只显示账号、昵称、类型、状态、创建/更新时间和操作；关键词、类型、状态筛选正确；新增使用双次密码，编辑只改昵称/状态，重设密码使用独立弹窗；表单在输入与失焦时校验，保留必填星号并关闭标签冒号；不再出现已删除模型字段；允许多个超级管理员，账户类型创建后不可修改。

## TC-04 账户错误输入

提交活动或已软删除账户使用过的重复用户名、无效账户类型、弱密码及缺少必填字段；尝试自禁用、自删除和禁用/删除最后一个启用的超级管理员。

期望：前后端一致拦截；用户名不能复用软删除历史；无法移除最后一个启用的超级管理员，错误提示明确且不泄露敏感信息。

## TC-05 非账户治理接口已移除

调用旧角色、租户、路由、权限及授权接口。

期望：接口不存在或返回统一的不可用结果，不执行任何写入。

## TC-06 治理审计查询已移除

访问旧治理审计路由并调用旧查询接口。

期望：页面和查询接口均不存在，前端生成客户端无对应调用。

## TC-07 新密码存库与登录

创建测试账户并核对存库格式，再用正确和错误密码登录。

期望：存库值为 48 字符交织格式，16 位数字盐由 Node `crypto` 生成；正确密码成功、错误密码失败；只记录脱敏证据。

## TC-08 改密与管理员设密

分别执行本人改密和管理员设密。

期望：旧密码失效，新密码可登录，两条路径使用同一存库格式；目标账户全部旧 Session 立即失效。

## TC-09 既有 Argon2 账户失效与恢复

使用隔离的既有 Argon2 账号验证旧密码；通过环境变量或一次性运维参数恢复测试超级管理员，再由其在账户页为另一个测试账户设置新密码。

期望：旧密码登录失败；超级管理员恢复入口不依赖仓库内默认密码；其他账户重新设密后存库为 48 字符格式并可登录，过程中不输出密码、盐或哈希。

## TC-10 管理端身份

分别用 `SUPER_ADMIN`、`PLATFORM_STAFF` 登录 Admin、BFF 网关管理端和 Portal。

期望：只有 `SUPER_ADMIN` 可进入两个管理端；`PLATFORM_STAFF` 被管理端拒绝，但可完成 Portal 登录和普通代理；全程不查询角色表。

## TC-11 Session ForwardContext

登录并刷新 Session，读取 Portal 账户信息与授权结果，再调用一个允许的代理接口。

期望：ForwardContext 可构建和刷新，Portal 动态路由/权限稳定返回空集合，代理链路成功且无角色依赖异常。

## TC-12 数据迁移边界

在隔离库执行迁移预检和回滚验证。

期望：只由 `adx-admin-backend` 迁移；保留账户数据，租户类型迁为 `PLATFORM_STAFF`；添加用户名永久唯一约束前能发现历史重复值；全部旧 Session 被吊销；删除对象与 Q1/Q3 一致。

## TC-13 自动回归和审核

运行测试策略全部命令，并对实际差异执行 code review、修复和复验。

期望：本轮新增失败为 0，P0/P1/P2-open 为 0。

## SR-01 账户单一化直接浅回归

1. 复核 Admin 只保留账户入口，账户列表、筛选、新增、编辑、启停、重设密码和软删除的主路径可达。
2. 复核正确/错误密码、旧格式拒绝、Session 吊销及 `SUPER_ADMIN`/`PLATFORM_STAFF` 门禁的关键分支。
3. 先使用定向自动化；只有取得本机服务和隔离库授权后，才补充运行态浅回归。

期望：本轮直接改动的账户、密码、Session 和管理端门禁没有新增失败；未获授权的运行态步骤明确保持未测。

## SR-02 BFF 保留能力相邻浅回归

1. 运行普通单发/批量代理和 HTTP 直通的既有定向测试，不修改接管前 HTTP 直通 dirty。
2. 运行接口编辑相关现有检查，并核对账户治理目录只影响已删除的治理入口。
3. 在取得本机服务授权后，各检查一次请求查询和实时日志的关键可见结果。

期望：普通代理、接口编辑、请求查询和实时日志没有因账户单一化产生新增失败；检查到范围外既有基线时保留证据并停止扩大范围。
