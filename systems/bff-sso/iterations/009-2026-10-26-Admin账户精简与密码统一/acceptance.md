# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01、TC-02 | Admin 登录后只存在账户管理入口，访问已删除页面不会重新出现旧页面。 | 通过 |
| AC-02 | TC-03、TC-04 | 账户列表与筛选只使用最终账户字段；新增、编辑、启停、独立重设密码和软删除可正常完成，不依赖已删除模型；表单在输入与失焦时校验、保留必填星号并关闭标签冒号；用户名跨软删除历史永久唯一；无法自禁用/自删除或移除最后一个启用的超级管理员。 | 通过 |
| AC-03 | TC-05、TC-06 | 非账户治理和治理审计查询接口均已移除，生成客户端与页面无残留调用。 | 通过 |
| AC-04 | TC-07、TC-08 | 新设和修改密码按 48 字符交织格式存库，数字盐由 Node `crypto` 生成；正确密码可登录、错误密码被拒绝，数据库和日志不出现明文。 | 通过 |
| AC-05 | TC-08、TC-09 | 现有 Argon2 账户旧密码登录失败；通过一次性安全参数恢复超级管理员后，可在账户页把其他账号设为 48 字符格式并恢复登录；重设、禁用或删除会立即吊销目标 Session。 | 通过 |
| AC-06 | TC-10、TC-11 | 只有 `SUPER_ADMIN` 可进入两个管理端；`PLATFORM_STAFF` 可进行 Portal 登录与普通代理，Portal 空授权合约和 ForwardContext 无角色依赖。 | 通过 |
| AC-07 | TC-12 | 数据迁移只在 `adx-admin-backend`；租户类型迁为 `PLATFORM_STAFF`、关系字段和非账户表按决策删除，历史用户名唯一性预检、全部旧 Session 吊销与回滚边界可复核。 | 通过 |
| AC-08 | TC-13 | 五个项目的定向测试、构建及代码审核全部通过，P0/P1/P2-open 为 0。 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。
