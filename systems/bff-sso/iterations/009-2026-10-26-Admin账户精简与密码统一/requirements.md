# 需求与注意事项：Admin 账户精简与密码统一

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

当前账号权限管理后台同时维护租户、角色、账号、账户关系、页面路由、权限、六类授权关系和治理审计。账户创建、登录身份、Portal 菜单授权及 BFF 管理权限仍与这些模型交织，维护成本高于本次目标。

本轮把 Admin 系统收敛为账户管理，并让新系统密码存库逻辑对齐 `/Users/mrzater/java/mergex-manager`。只读源码已确认参考项目使用自定义 48 字符“16 位随机盐与 32 位 MD5 摘要交织”格式，不是普通 MD5，也不是当前系统使用的 Argon2。

## 本次要做

### 页面

- `adx-admin-frontend` 最终只保留登录、账户管理和维持页面运行所必需的壳层。
- 删除概览、租户、角色、账户体系关系图、页面路由、权限及全部关联管理页面、菜单和路由。
- 删除截图中的治理审计日志页面、菜单、路由及其前端调用代码。
- 账户列表展示账号、昵称、账户类型、状态、创建时间、更新时间和操作；支持按账号/昵称关键词、账户类型和状态筛选。
- 新增账户填写账号、密码、确认密码、昵称、账户类型和状态；编辑时账号、账户类型只读，只允许修改昵称与状态。
- 重设密码使用独立弹窗；操作保留编辑、启用/禁用、重设密码和软删除，不再展示或提交创建者、父级、角色、租户字段。
- 新增、编辑和重设密码表单统一在输入与失焦时校验，保留必填星号并关闭标签冒号，不能通过隐藏必填提示弱化约束。

### 接口与保存

- Admin 对外治理能力只保留账户查询和账户增删改所需接口；删除非账户治理 CRUD、授权与治理审计查询接口。
- 角色、租户、路由、权限及授权模型和接口全部删除；SSO 登录、BFF 超管校验和会话 ForwardContext 必须改用账户权威字段，不能以删表造成运行时 500/403。
- 账户类型只保留 `SUPER_ADMIN`、`PLATFORM_STAFF`；仅 `SUPER_ADMIN` 可进入 Admin 账户管理和 BFF 网关管理，`PLATFORM_STAFF` 只保留 Portal 登录与普通代理会话。
- 允许多个 `SUPER_ADMIN`；只有超级管理员能创建两类账户，`accountType` 创建后不可修改；禁止自禁用、自删除，并始终保留至少一个启用的超级管理员。
- 密码生成、校验、修改和管理员设密统一使用参考项目的 48 字符“16 位数字盐与 32 位 MD5 摘要交织”格式，密码最少 8 位；数字盐由 Node `crypto` 生成，不兼容现有 Argon2，也不复制参考项目的浏览器 RSA 传输层。
- 保留 Portal 登录和账户信息合约；删除动态路由/权限计算，原授权结果返回稳定空集合，Portal 页面路由由调用方静态维护。
- 旧密码失效后，只通过环境变量或一次性运维参数重设超级管理员；其他账户由超级管理员在账户页重设，初始密码不得硬编码或写入仓库。
- 管理员重设密码、账号禁用或软删除后立即吊销目标账号全部 Session；本次身份模型与密码格式迁移上线时统一吊销全部旧 Session。
- `mergex-manager` 只作为只读算法参考，不修改该仓库。

### 数据

- 账户主体数据必须保留；账户的 `parentId`、`creatorAccountId`、`updatedAccountId`、`tenantId` 等关系字段删除，保留 `yn` 软删除标记和普通时间戳；`accountType` 只允许 `SUPER_ADMIN`、`PLATFORM_STAFF`。
- 账户始终软删除；用户名在全部历史记录中永久唯一，删除后不可复用，本轮不提供恢复页面。
- 数据库变更只允许在 `adx-admin-backend` 建立 Prisma 迁移；BFF 与 SSO 只能同步所需模型。
- 物理删除只适用于本轮明确废弃的非账户治理表；账户记录继续软删除。任何删表或清理废弃治理历史数据的迁移都必须在计划阶段列出备份、顺序和回滚边界，实施前不得直接执行迁移。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 新建账户 | 使用 48 字符“16 位数字盐与 32 位 MD5 摘要交织”格式；不再依赖已删除的页面或接口。 |
| 已有账户 | 保留账户主体；不兼容现有 Argon2，旧密码允许失效；先安全恢复超级管理员，再由其在账户页为其他账户重新设密。 |
| 已有租户类型账户 | `TENANT_ADMIN`、`TENANT_STAFF` 统一迁为 `PLATFORM_STAFF`，删除 `tenantId`；迁移后不获得两个管理端访问权。 |
| 已软删除账户 | 保留历史行并纳入用户名唯一性检查，不允许新账户复用其用户名。 |
| 既有 Session | 上线迁移时统一吊销；此后密码重设、禁用或删除只吊销目标账户全部 Session。 |
| 已有角色、租户、路由、权限和授权数据 | 迁移前备份，随后通过 `adx-admin-backend` 的迁移删除，不再作为内部运行数据。 |
| 已有审计数据 | 删除治理审计查询面与无意义治理写入；保留 BFF 登录、代理及网关请求运行日志所需记录。 |

## 不做

- 不修改 `/Users/mrzater/java/mergex-manager`。
- 不删除网关“请求查询/实时日志”及登录、代理安全审计。
- 本规格阶段不修改五个产品仓库，不提交、不推送、不部署、不执行数据库迁移。
- 不借本轮重做页面视觉风格。

## 注意事项

- `mergex-manager` 的 48 字符随机盐 MD5 明显弱于 Argon2，若采用必须在决策和风险中显式记录安全降级。
- 浏览器 RSA 传输解密与密码存库格式是两件事；本轮只统一存库格式，不复制参考项目的 RSA 传输层。
- 文件列表见改动范围，这里不重复贴路径。
