# 需求与注意事项：平台服务直连

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

账号后端要通知网关踢掉登录，也要通知登录服务设置密码。这两次调用现在都只到 Nacos 里找对方，再从那台机器下载接口文件。

配置里已经有 `BFF_GRPC_URL`、`SSO_GRPC_URL`，代码没有拿来连。没有这两个地址时，Nacos 里找不到实例，踢登录和设密码都会失败。

这一轮要让账号后端可以继续用 Nacos，也可以改用配置里的固定地址。登录、停用、删除这些结果保持不变。

## 本次要做

### 页面

没有页面。切换方式写在配置里，不做到管理页上。

### 接口与保存

账号后端去找网关、去找登录服务，各有一个接入方式：

- `BFF_ACCESS_TYPE`：`nacos` 或 `direct`
- `SSO_ACCESS_TYPE`：`nacos` 或 `direct`

`nacos` 保持现在的做法：按分组和服务名找健康实例，从那台机器下载接口文件。网关的服务名仍是 `NACOS_BFF_SERVICE_NAME`，登录服务仍是 `NACOS_SSO_SERVICE_NAME`。启动时仍只订阅网关，不订阅登录服务。

`direct` 时：

- 网关地址用 `BFF_GRPC_URL`，接口文件用 `BFF_SESSION_PROTO_PATH`。
- 登录服务地址用 `SSO_GRPC_URL`，接口文件用 `SSO_PROTO_PATH`。
- 不再向 Nacos 问这个目标，也不从对方机器下载接口文件。
- 网关若是 `direct`，启动时不要订阅网关。登录服务本来就没有启动订阅，保持这样。

踢登录仍是原来的调用，方法名是 `RevokeByAccount`。请求仍带原来的内部令牌。会触发的操作不变：

- 停用账号
- 删除账号
- 停用角色，并踢掉绑在这个角色上的账号
- 删除角色，并踢掉绑在这个角色上的账号

设密码仍是原来的 `SetPassword`。直连只换地址和接口文件从哪来，不改请求内容。

选了 `direct` 但地址或接口文件路径是空的，这次调用失败，并说明缺哪一项。不能改去问 Nacos。

### 数据

不改数据库，不改接入服务那张表。001 轮已经让网关按接入服务记录去找后面的服务，这一轮不动那条路。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 没有写 `BFF_ACCESS_TYPE` 或 `SSO_ACCESS_TYPE` | 按 `nacos`。已经在跑的配置不用改。 |
| 写成 `nacos` | 跟现在一样找实例、下载接口文件。固定地址可以留着，但这次调用不用它。 |
| 写成 `direct` 且地址、接口文件路径都有 | 只连配置里的地址，用本地接口文件。 |
| 写成 `direct` 但地址或接口文件路径为空 | 调用失败，不退回 Nacos。 |
| 两个目标 | 可以一个用 `nacos`、另一个用 `direct`。 |

## 不做

- 不改「自己的配置从 Nacos 拉还是只读本地 `.env`」。`NACOS_CONFIG_ENABLED` 仍是原来的启动开关。
- 不取消账号后端、登录服务把自己注册到 Nacos。注册和「去找别人」是两件事。
- 登录服务不去调用网关踢登录。踢登录只由账号后端发起。
- 普通接入服务怎么保存、怎么转发，仍按 001，这一轮不改。
- 登录服务和账号后端由网关启动时同步。没有记录才新建，新建时写入 Nacos 拉到的直连地址。已有记录不新建。已有记录是否更新地址，看网关 Nacos 配置 `SYNC_DIRECT_ADDRESS`：`false` 或不写时不更新；`true` 时更新地址并把接入方式写成直连。内建和普通记录都适用。配置里没有地址时，不新建，也不把已有地址改成空。
- 不改管理页，不改浏览器能看到的文案。
- 不改数据库表，不在这一轮做迁移。

## 注意事项

- 文件列表见改动范围，这里不重复贴路径。
- 地址和接口文件路径放配置，不写进代码。
- 文档和示例里不要写真实内网地址、密码、令牌。示例地址用 `192.0.2.10:5003` 这种文档地址。
