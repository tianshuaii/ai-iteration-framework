# 需求与注意事项：Nacos 配置瘦身与代码配置外置

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

`adx-bff-backend`、`adx-admin-backend`、`adx-sso-backend` 都从 Nacos 拉取自己的 YAML 配置。2026-10-28 只读盘点显示：dev/test 环境的 BFF 分别有 60/53 项、Admin 有 31/24 项、SSO 有 21/20 项。大量固定默认值、重复服务标识和 Nacos 自身启动参数与业务运行参数混在同一份远端配置中，维护成本高，也不容易判断删掉一项是否会影响启动。

同时，BFF 代码里仍有一批会影响安全、性能或环境连通性的运行参数使用代码默认值或直接读取 `process.env`，没有统一进入强类型配置；需要区分哪些应外置、哪些是协议或业务常量，应继续留在代码中。

## 已核实的现状

- `.env` / `.env.test` 负责首次连接 Nacos；远端 YAML 在首次连接成功后才加载。
- 远端 YAML 中的 `NACOS_CONFIG_GROUP`、`NACOS_CONFIG_TIMEOUT_MS` 无法影响本次首次拉取，只能影响加载完成后的配置对象，存在层级错位。
- 三仓普遍同时配置 `SERVICE_NAME`、`NACOS_SERVICE_NAME`、`NACOS_APP_NAME`；当前代码已有回退链，可压缩为一个稳定来源。
- `NACOS_CLIENT_TRANSPORT=grpc` 已是唯一合法值；group、cluster、weight、ephemeral、fail-fast 等多项在 dev/test 完全相同并等于代码默认值。
- BFF 的 Session 授权刷新、运行包缓存容量/对账周期/发布超时和登录失败退避目前主要依赖代码默认值，属于候选外置项。
- 服务编码、Proto 文件名、gRPC full method、Redis key/channel 协议版本等是跨实例契约或业务标识，不应仅因“写在代码里”就全部移入 Nacos。

## 本次要做

### 配置清单

- 对三份后端 Data ID 的 dev/test 真实键做分类：保留、移回最小 bootstrap、依赖代码默认后删除、从代码外置新增、暂缓。
- 每个键记录使用方、默认值、是否跨环境变化、删除或外置后的启动行为，不输出真实密钥或连接串。
- 给出瘦身前后数量和差异清单，禁止用“看起来没用”作为删除依据。

分类必须至少覆盖以下规则：

| 分类 | 代表项 | 目标处理 |
|---|---|---|
| 首次拉取前必需 | `NACOS_CONFIG_GROUP`、`NACOS_CONFIG_TIMEOUT_MS`、Nacos 地址/命名空间/账号 | 只留在 `.env` bootstrap 层，不放回被拉取的远端 YAML |
| 重复服务身份 | `SERVICE_NAME`、`NACOS_SERVICE_NAME`、`NACOS_APP_NAME` | 保留一个权威来源，其余由代码派生；跨服务目标名仍单独保留 |
| 稳定且等于代码默认 | transport、cluster、weight、ephemeral、fail-fast、固定 metadata、公共长度/超时默认 | 从远端删除，由强类型默认值和测试保护 |
| 环境差异或敏感值 | 数据库、Redis、JWT/内部令牌、平台主密钥、服务地址、端口、项目 ID | 按实际环境保留；敏感正文不入文档和快照 |
| 运维可调开关与策略 | 日志级别、注册开关、功能开关、JWT/Session 策略、批量请求上限 | 只有确需覆盖时保留；等于默认且无环境差异时允许删掉 |
| 跨实例协议常量 | Proto 文件/方法、服务编码、Redis key/channel 版本、构建期开关 | 留在代码，不迁入 Nacos |

### 代码与模板

- 清理远端配置中层级错误、重复且等于稳定代码默认值的键。
- 让三仓 `app.config.ts`、本地 `nacos-config.*.yml` 模板、环境示例和测试保持同一配置契约。
- 把经确认的安全/性能/环境运行参数从散落常量或裸 `process.env` 收口到强类型配置；协议常量、业务稳定键和构建期开关继续留在代码。
- 增加最小“精简配置仍可启动校验”的自动测试，防止后续又把无效 bootstrap 键放回远端。

BFF 本轮允许新增的外置项限定为：

- 登录失败窗口、失败阈值、基础锁定时长、最大锁定时长四项安全参数。
- Session 授权租户刷新周期。
- 运行时接口缓存容量、对账周期、发布超时。
- 经调用链证明仍存在环境差异的 HTTP 上游 origin；没有消费者或已有服务发现替代时不得为“以后可能用”新增配置。

这些新增项必须保持现有代码行为为默认值，并由统一强类型配置消费。日志队列容量、内部重试细节等没有明确运维需求的实现参数不新增到 Nacos。

### Nacos 数据

- 实际远端发布按环境分批、读后校验，并保留发布前键名清单和回滚正文摘要；不得在规格或计划阶段发布。
- 发布顺序固定为 test 后 dev；每个 Data ID 单独发布、读回、完成启动/配置解析验证后才进入下一个，任一失败立即停止。
- prod 只输出按键分类和迁移顺序，不读取、不发布、不删除生产配置。
- 密钥和值不写入迭代文档、日志或测试快照。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 未显式配置稳定默认项 | 使用代码中唯一、受测试保护的默认值 |
| 已显式配置且与默认值相同 | 经确认后从远端移除，运行行为不变 |
| 已显式配置且跨环境不同 | 保留在对应环境 Nacos |
| 必填密钥、连接串或主密钥 | 不因瘦身自动删除；缺失继续启动失败 |
| 从代码外置的新参数 | 先保持原代码默认值等价，再允许各环境显式覆盖 |
| 远端发布失败或读后差异异常 | 立即停止后续环境，使用发布前正文回滚 |

## 不做

- 不把所有代码常量机械迁入 Nacos。
- 不改变数据库 Schema、接口协议、鉴权语义或业务功能。
- 不在未取得单独外部写入授权时发布或删除任何 Nacos 配置。
- 不把 Nacos 密钥治理扩展成新的 Secret Manager 建设，除非访谈另行决定。
- 不修改两个前端仓库。

## 注意事项

- 这是多仓、外部配置和安全敏感改动，使用 `strict` 档位。
- Nacos 远端修改属于外部写入，实施时必须另行取得明确授权。
- 文件列表见改动范围，这里不重复贴路径。
