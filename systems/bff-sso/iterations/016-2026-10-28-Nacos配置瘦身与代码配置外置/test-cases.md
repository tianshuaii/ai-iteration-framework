# 测试用例

前置：只读盘点使用当前 dev/test 六个 Data ID；敏感值只在进程内参与校验，不输出到文档。远端发布用例只有取得明确外部写入授权后才执行。

## TC-01 六份配置逐键分类

1. 分别取得 BFF、Admin、SSO 的 dev/test 键名和远端 revision。
2. 将每个键映射到代码消费者、默认值、环境差异和分类规则。
3. 检查报告是否含疑似密码、令牌、连接串正文。

期望：六份配置无漏键、无无依据删键，所有敏感值均被脱敏。

## TC-02 精简模板默认等价

1. 对三个后端的 dev/test 精简模板执行 Schema 解析测试。
2. 删除稳定默认键后，对比关键配置对象与改前默认结果。
3. 对确需环境覆盖的键各执行一次显式覆盖。

期望：六份模板均可解析；未配置时行为不变，覆盖值按类型生效。

## TC-03 bootstrap 与 runtime 分层

1. 仅通过 `.env` 示例提供 Nacos 首次连接、命名空间、Data ID、group 和超时。
2. 检查远端模板不再包含本次拉取无法消费的自举键。
3. 缺少一个必需 bootstrap 键执行配置准备。

期望：完整 bootstrap 可以定位远端配置；缺项明确失败；远端模板不反向决定首次拉取。

## TC-04 服务身份唯一来源

1. 每个服务只设置权威本服务名并生成注册参数。
2. 检查 app name、registration service name 的派生结果。
3. 分别检查 BFF/Admin/SSO 的跨服务目标名。

期望：本服务身份无三份重复配置，注册结果与改前一致，跨服务发现不串名。

## TC-05 BFF 高价值参数外置

1. 不配置新增键，验证登录限流、Session 刷新和运行时接口缓存参数。
2. 为八个允许外置项设置合法覆盖值并验证消费者收到新值。
3. 输入零值、负数、非数字或越界值。

期望：默认行为与改前一致；合法覆盖生效；非法值在启动配置校验阶段被拒绝。

## TC-06 敏感必填项不降级

1. 分别移除数据库连接、内部令牌、JWT 密钥和平台主密钥等当前必填项。
2. 执行三仓配置解析或对应定向测试。

期望：缺失项明确指出配置名并失败，不产生空字符串、固定密钥或开发默认值。

## TC-07 dev/test 分批发布与回滚

1. 取得授权后保存目标 Data ID 的发布前 revision、键名和加密/受控回滚正文。
2. 按 test→dev、每次一个 Data ID 发布精简配置并立即读回。
3. 执行该服务配置解析或启动验证；模拟一份读回不一致并执行回滚。

期望：成功项远端正文与计划摘要一致；异常时后续 Data ID 未发布，当前项恢复到原 revision 对应内容。

## TC-08 生产迁移边界

1. 生成生产迁移清单，包含键分类、依赖、顺序、验证和回滚要求。
2. 检查操作记录和证据目录。

期望：清单不含生产值，且没有生产 Nacos 读取、发布、删除或启动操作。

## TC-09 三端契约构建检查

1. 分别执行三个后端的配置定向测试和现有构建。
2. 核对新增配置仅由统一强类型配置模块消费。

期望：三仓检查通过，不残留本轮计划清理的重复裸 `process.env` 读取。

## 受控浅功能回归用例

按 `test-strategy.md` 的 `SR-xx` 逐条增加二级标题、前置、简短步骤和期望。只验证主路径与关键可见结果，不穷举全部边界。

## SR-01 精简配置加载与注册参数

前置：使用不含稳定默认冗余键的 dev/test 模板。

1. 加载 BFF、Admin、SSO 配置。
2. 生成各自服务注册参数并核对服务名、group、cluster、端口。

期望：配置加载成功，注册参数与瘦身前等价。

## SR-02 BFF 参数消费者浅回归

前置：分别准备默认配置和一组合法覆盖配置。

1. 触发登录失败计数与锁定时长计算。
2. 触发 Session 授权租户刷新周期读取。
3. 初始化运行时接口缓存并执行一次对账/发布超时路径。

期望：默认配置保持旧行为，合法覆盖只影响对应消费者，不影响其他认证和转发逻辑。
