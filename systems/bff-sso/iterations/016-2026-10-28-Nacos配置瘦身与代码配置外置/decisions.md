# 决策记录

| 编号 | 决定 | 原因 | 没采用的做法 |
|---|---|---|---|
| D-01 | 远端配置和值只做脱敏盘点，迭代文档不保存密钥、连接串和令牌正文 | 配置治理不能制造新的敏感信息泄露面 | 把完整 Nacos YAML 复制进迭代目录 |
| D-02 | 协议常量、业务稳定标识和构建期开关不因“硬编码”自动外置 | 这类值要求各实例一致，错误外置会增加漂移风险 | 把所有常量都迁入 Nacos |
| D-03 | 本轮完成审计、代码和模板瘦身；dev/test 远端发布必须另行取得外部写入授权 | 先把可验证契约落到代码，再分环境发布，避免一次性删键导致三个服务同时失效 | 只交审计报告，或在规格阶段直接修改远端配置 |
| D-04 | dev/test 进入实际实施范围，prod 只输出迁移清单且不写入 | 当前只取得 dev/test 的真实键证据，没有生产配置和生产变更授权 | 直接把 dev/test 结论复制到生产环境 |
| D-05 | Nacos 只保留环境差异、敏感值、地址端口和明确需要运维覆盖的参数 | 稳定默认值留在强类型代码中更容易测试，也能减少跨环境漂移 | 每个默认值都在 Nacos 重复声明 |
| D-06 | 本轮敏感配置继续由 Nacos 承载，不建设 Secret Manager | 控制改动范围，同时保持现有部署方式 | 在配置瘦身中顺带迁移全部密钥管理体系 |
| D-07 | 只外置高价值安全、性能和环境参数；协议标识与稳定业务常量继续留在代码 | 可调参数需要运维覆盖，协议常量需要所有实例一致 | 把日志内部队列、Proto 方法和 Redis 协议键全部外置 |
