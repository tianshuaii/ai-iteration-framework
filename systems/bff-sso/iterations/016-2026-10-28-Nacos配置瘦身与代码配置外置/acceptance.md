# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | dev/test 六份远端配置的每个键均有消费者、分类、环境差异和去留结论；报告不含密钥、连接串或令牌正文 | 通过 |
| AC-02 | TC-02 | 三仓精简后的 dev/test 模板均能通过配置 Schema；删除稳定默认键后解析结果与原行为等价 | 通过 |
| AC-03 | TC-03 | 首次拉取 Nacos 所需参数只由 bootstrap 环境提供，远端模板不再声明无法影响本次拉取的自举键 | 通过 |
| AC-04 | TC-04 | 每个服务只有一个本服务身份权威来源，注册名和应用名按明确回退派生；跨服务目标名不受影响 | 通过 |
| AC-05 | TC-05 | BFF 新增的登录限流、Session 刷新和运行时接口缓存参数全部进入强类型配置，未配置时保持旧行为，显式覆盖时生效 | 通过 |
| AC-06 | TC-06 | 数据库、内部令牌、JWT/平台主密钥等必填敏感项缺失时继续明确启动失败，不因瘦身获得不安全默认值 | 通过 |
| AC-07 | TC-07 | 获得外部写入授权后，按 test→dev、逐 Data ID 发布并读回校验；任一异常停止后续发布且能用发布前正文回滚 | 通过 |
| AC-08 | TC-08 | 生产环境只有脱敏迁移清单，没有生产 Nacos 读取、发布或删除记录 | 通过 |
| AC-09 | TC-09、SR-01、SR-02 | 三端服务注册/发现、BFF 登录限流与 Session/运行时接口缓存的主路径没有因配置收口改变业务语义 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。
