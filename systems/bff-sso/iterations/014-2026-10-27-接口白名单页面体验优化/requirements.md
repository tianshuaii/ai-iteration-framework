# 需求与注意事项：接口白名单页面体验优化

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

网关管理的「接口白名单」页能用，但不好看，也不好用。搜索、筛选、保存和「已选多少条」挤在同一行。列表一长，保存就滚出视线。勾了还没保存时，看不出和已保存名单有什么差别。方法、路径、摘要排在普通表格里，接口一多就不好扫。

这一页的功能本身不用改：仍按顶栏选中的接口项目，只给 HTTP 项目勾选默认分支上的原接口。勾中的接口走唯一路径时不用登录，没勾的仍要登录。名单空着表示都要登录。

## 本次要做

### 页面

- 只改这一页的排法和操作感受。配色继续用现在的管理端：浅灰底、白侧栏、近黑按钮、当前菜单蓝色。
- 页头仍说明：勾中的接口走唯一路径时不用登录，没勾的仍要登录，名单空着表示都要登录。句子可以改短，意思不能变。
- 没选项目时仍显示「请先在顶栏选择接口项目」。gRPC 项目仍显示「gRPC 项目不保存白名单」。没有原接口时表格仍显示「先到原接口文档导入原接口」。
- 搜索、筛选、已选数量、保存，以及「其中 N 条已经不在当前原接口里」这句警告，固定在列表上方。列表再长，这一条也看得到。窄屏时搜索和筛选可以换行，保存仍留在这一条里。
- 继续用表格勾选。方法用能区分的标签，路径是主文字，摘要是次要文字。窄屏表格可以横滑。不改成树，也不改成卡片墙。
- 勾选和已保存名单不一致时，保存旁边写「有未保存的修改」。保存成功后这句话消失。搜索和「已加入 / 未加入」筛选留着。

### 接口与保存

- 保存仍只提交当前勾选的白名单，不带项目名称和其他字段。
- 保存成功仍提示「白名单已保存」。保存失败仍提示「保存失败」。
- 不新增接口，不改请求字段和返回字段。

### 数据

- 不改已保存的白名单。打开页面时仍显示服务端已保存的勾选。
- 换项目后，上一个项目的勾选草稿和筛选不能带到下一个项目。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 打开已有白名单 | 勾选与现在保存的名单一致，不出现「有未保存的修改」。 |
| 改了勾选还没保存 | 保存旁边出现「有未保存的修改」，名单先不写入服务端。 |
| 还没保存就换项目 | 草稿丢掉，回到那个项目已保存的名单。 |
| 保存成功 | 勾选草稿清掉，未保存提示消失，搜索和「已加入 / 未加入」筛选留着。 |
| 名单里有当前原接口已经没有的项 | 仍留在已选数量里，警告和保存一起留在列表上方。 |
| gRPC 或未选项目 | 仍不展示可勾选列表，也不允许在这一页保存。 |

## 不做

- 不改谁免登录、谁必须登录。
- 不改搜索规则、筛选规则、勾选规则和保存内容。
- 不改账号权限后台，不改后端，不改运行包抽屉里的白名单展示。
- 不换整套管理端配色，不做深色底、绿色按钮、毛玻璃或等宽字体。
- 不把列表改成树或卡片墙。

## 注意事项

- 这一页没有新增必填表单。搜索框继续只做过滤，不出必填星。
- 文件列表见 [change-scope](./change-scope.md)。
