# 测试用例

前置：有一个已配置请求密钥、已绑定平台账号的 HTTP 接入平台；有一条白名单接口和一条非白名单接口。不写密钥明文。不改 `mergex-manager` 代码。

## TC-01 登录前白名单

1. 不带 BFF Session。
2. 打一条白名单 HTTP 直通。

期望：请求能到上游或按现有白名单规则成功。抓到的上游请求没有 `X-BFF-Secret`、没有 `X-BFF-User-Id`，也没有调用方 BFF Authorization。

## TC-02 登录前需登录接口

1. 不带 BFF Session。
2. 打一条非白名单、非平台登录的 HTTP 直通。

期望：BFF 拒绝。上游收不到这次请求，或至少收不到平台身份头。

## TC-03 登录时接管

1. 不带 BFF Session，打已登记的平台登录接口。
2. 分别看上游业务失败和业务成功两种。

期望：失败时状态、头和正文按现有规则原样回，且不建 Session。成功时返回 BFF 登录信封，能拿到可用 Token。

## TC-04 登录后身份头

1. 用平台登录拿到的 Token 打非白名单接口。
2. 看 BFF 发往上游的请求头。

期望：有且只有服务端写入的 `X-BFF-Secret` 和 `X-BFF-User-Id`。没有调用方 Authorization / Bearer token。

## TC-05 登录失效

1. 让 Session 过期或主动清掉后再打非白名单接口。

期望：BFF 拒绝。不再用旧平台上下文注入身份头。

## TC-06 缺陷分仓

1. 看本轮缺陷清单。

期望：每条都有责任侧。`bff-sso` 的已修或明确无缺陷。`mergex-manager` 的只留清单和该系统新轮次指向，本轮 git 未改那边仓库。

## 受控浅功能回归用例

## SR-01 四段主路径

前置：同本文件前置。

1. 按 TC-01 → TC-03 成功支 → TC-04 → TC-05 各做一次。

期望：四段都符合对应 TC。停止在这一条平台链，不穷举其他上游。

## SR-02 相邻登录仍可用

前置：BFF 管理端或 Portal 原登录可用。

1. 做一次原 BFF Portal 或 Admin 登录，或看健康检查。

期望：仍可用。不检查账号权限后台菜单，不打 gRPC `/proxy/one`。
