# 改动范围

## 可以改

| 仓库或目录 | 说明 |
|---|---|
| `adx-bff-backend` | HTTP 直通、登录接管、平台身份头注入、Session 失效处理等相关缺陷。具体文件等定位后补。 |
| `adx-bff-frontend` / `adx-sso-backend` / `adx-admin-backend` / `adx-admin-frontend` | 仅当排查证明缺陷在这些仓时才纳入；默认先不动。 |
| 本轮迭代文档与证据 | 四段审计记录、缺陷清单、指向 `mergex-manager` 新轮次的记录。 |

## 现在对照的行为

| 状态 / 位置 | 现状（只读核对） | 本轮目标 |
|---|---|---|
| 登录前 · 白名单 | 不要求 Session，不注入平台身份头 | 保持；若误要求登录或误注入则修 BFF |
| 登录前 · 需登录接口 | 应拦在 BFF，不带着假身份打到上游 | 确认未登录不会误注入密钥和用户编号 |
| 登录时 · 平台登录 | 免 Session；上游响应可被接管 | 与 002 / 012 登录返回形态对齐；缺陷按仓归类 |
| 登录后 · 非白名单 | 注入 `X-BFF-Secret`、`X-BFF-User-Id`，不转发调用方 Authorization | 与 002 约定一致；若不一致则修 BFF |
| 登录失效 | Session 无效时应拒绝，不继续用旧上下文注入 | 确认不会把过期身份转给子服务 |
| MergeX 管理端 002 | 两头齐全且正确时按用户放行，不看 token | 本轮不改；发现问题马上另开 `mergex-manager` 迭代 |

## 不许改

| 仓库或范围 | 原因 |
|---|---|
| `mergex-manager` | 用户要求本轮不直接改；另开该系统迭代 |
| `mediatom-web` | 同上，属 `mergex-manager` 系统页面仓 |
| `mergex-datasyn` | 不在本轮转发主链 |
| gRPC `/proxy/one`、账号权限后台 | 先不扩；除非审计证明断点在那里 |
| 无关功能与密钥明文入档 | 本轮是缺陷排查与定点修复 |

定位完成前先留空，找到 `bff-sso` 侧缺陷后再逐条补路径。
