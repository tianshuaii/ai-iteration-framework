审计依据：`evidence/analysis/forward-audit.md`。责任侧只写 `bff-sso`、`mergex-manager` 或 `无`。

| 编号 | 状态段 | 现象 | 责任侧 | 处理 |
|---|---|---|---|---|
| 无 | 登录前白名单 | 源码与单测均显示不注入身份头、不转发 Authorization | 无 | 无需改代码 |
| 无 | 登录前需登录 | 缺 Session 时拦在 BFF，不注入身份 | 无 | 无需改代码 |

| 无 | 登录失效 | Session 失效或平台上下文失效时拒绝，不继续注入 | 无 | 无需改代码 |

## 汇总

- **bff-sso 缺陷：无**
- **mergex-manager 代码缺陷：无**（002 头判断与需求一致）

## 残余运维风险（不算本轮代码缺陷）

1. 接入平台在 BFF 配置的请求密钥，必须与 MergeX 管理端常量类密钥一致；不一致时管理端会拒绝两头请求。明文不入档。
2. 绑定的平台账号 ID 必须是 MergeX 可解析的整数用户编号；非数字编号会被管理端拒绝。
3. 未授权启动联调服务前，四段结论以源码与定向单测为准。
