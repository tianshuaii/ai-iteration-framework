# 实现计划

## 做法

先只读审计，再按缺陷清单改 `bff-sso`。审计按登录前、登录时、登录后、登录失效四段，对照 `mergex-manager` 002 契约。责任在 MergeX 一侧的条目不进本轮代码，确认后马上在 `mergex-manager` 系统新开一轮。

默认只动 `adx-bff-backend` 的 HTTP 直通、登录接管和 Session 相关代码。审计若证明断点在别的 bff-sso 仓，再补任务，不提前扩范围。

## 任务拆分

1. **T-01 四段只读审计**：对照源码和（如有）现成故障单，写出缺陷清单，标明责任侧。本任务不改产品文件。
2. **T-02 修复本轮确认的 bff-sso 缺陷**：按清单改后端并补定向测试。若清单上没有 bff-sso 缺陷，本任务只提交“确认无 BFF 缺陷”的证据，不空改进程。
3. **T-03 对接 MergeX 侧缺陷**：把 `mergex-manager` 侧条目整理成可开轮材料；用户授权后在该系统创建新迭代。本任务不改 MergeX 源码。

## 风险与回退

- 审计不充分会漏掉失效态。必须单独覆盖登录失效。
- 误改白名单或登录接管会伤到现网路径。修复只动清单点名的文件，定向测试先过。
- 两边密钥不一致容易误判成 BFF 漏注。归类时先核对“是否发出”，不把密钥明文写入文档。

## 任务风险（与测试策略一致）

| 任务 | 档位 | 必须执行 |
|---|---|---|
| T-01 | T2 | 四段审计文档 + 责任侧清单 |
| T-02 | T3 | 定向单测与受影响 TC；无 BFF 缺陷则只留确认证据 |
| T-03 | T1 | handoff 文档；有 MergeX 缺陷时留下对端轮次路径 |

## 验证安排

- 自动：`adx-bff-backend` 直通 / 登录接管 / Session 相关定向测试。
- 手工：TC-01～TC-06、SR-01、SR-02。
- 不启动未授权服务；不写正式库。
