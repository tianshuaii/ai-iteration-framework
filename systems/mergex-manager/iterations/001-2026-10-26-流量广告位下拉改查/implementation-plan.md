# 实现计划

## 做法

不建表，不改 `publisher_traffic_place_link`。管理端自己加一个查询，读这张表里的供应商 ID 和流量广告位 ID。定时任务仓库不动。

新接口是 `POST /trafficPlace/searchPublisherTrafficPlace`，挂在现有流量广告位控制器上，登录要求和老下拉一样。请求带三个可空数组或字符串：`publisherIdList`、`searchKey`、`trafficPlaceIdList`。返回里每一行只有 `trafficPlaceId`。

匹配放在一处，页面不再自己拼「广告位 ID_流量广告位 ID」：

- 三个条件都空，直接返回空列表，不去扫表。
- 只有已选 ID：只把这些 ID 去重后回给页面，用来留住已经选中的项。
- 没选供应商、有关键字：只按关键字查。一个关键字按包含匹配；逗号、空格或回车分开的多个关键字按 ID 精确匹配。不按当前账号可见供应商再收一层。
- 选了供应商：只查这些供应商。搜索框为空也查，列出他们名下的去重 ID。有关键字就在这些供应商里按上面的规则匹配。
- 已选 ID 始终并进返回，即使它们不属于当前选中的供应商。新命中的 ID 仍然只来自选中的供应商。
- 空 ID 丢掉。同一个 ID 只留一行。不按广告位收窄。不设条数上限。

关键字怎么拆、结果怎么去重，写在现有 `TrafficPlaceServiceImpl` 里，单测直接调用，不连数据库。SQL 只按供应商和关键字查出 ID，放在新增的 Mapper 和 XML 里，目录跟现有 `TrafficPlaceMapper` 一样。老的 `getTrafficPlace` 和它的 Mapper 不改。

ADX 全量报表、导出和小时报表共用 `normalizeTrafficPlaceIdsForFullReport`。这里改成：有下划线就取第一个下划线后面的整段，没有下划线就整段保留。小时报表页面不改。

鲲鹏只改 `hasUnsupportedFilters`：`trafficPlaceIdList` 不再算不支持条件。广告位、接入类型、包名这些原有的不支持条件留着。`report_kunpeng` 的 SQL 不加流量广告位条件，也不先反查供应商。

多曝光的查询、下载、组装类和只给它用的返回对象删掉。共用的报表 Mapper、投影工具只删多曝光那几段。删之前先搜引用，别的报表还在用的方法留下。删完要能编译主代码和测试代码，主代码里不再留下多曝光的名字。

菜单不改前端写死的名单来“隐藏”。在 `mergex-manager/sql/` 放一条脚本：先查出 `route_config` 里组件名正好是 `FunlinkAnalyse` 的路由，确认只有这一条，再把它的 `status` 改成 `D`。JSON 里有没有空格，按库里这一行的真实写法匹配，不用宽泛的 `Funlink`。不物理删除。这条脚本本轮不执行。

页面只改 ADX 报表和鲲鹏报表的流量广告位下拉。两页都改成和应用包名一样的异步搜索，但供应商一变就再查，搜索框为空也查。两个都空时不请求。组件自带的搜索只在有关键字时触发，所以供应商变化要在页面自己的供应商监听里另外调用。已选 ID 放进 `trafficPlaceIdList` 带回。选项的值和展示都只用流量广告位 ID。两处下拉单独传入只提 ID 的搜索提示，中英文成对，不改组件的默认提示。

ADX 和鲲鹏的搜索页已经超过或接近 300 行，公共 mixin 也超过 300 行。已批准的文件名单里没有新文件。这轮只改流量广告位那几处，不借机拆文件。新的请求方法放进已经点名的 mixin，匹配规则不在前端再写一套。

多曝光页面目录、只给它用的前端接口、路由组件名、列缓存名和没有引用的文案删掉。聚合配置里的 funlink 编辑限制不碰。

## 为什么这样切

老接口还要给映射管理用，所以新查询单独加，不改老接口的返回。

ID 解析已经集中在一个方法里，全量报表、小时报表和多曝光都走它。只改这一处，页面不用各写一套。多曝光删掉之后，小时报表仍走这个方法，所以放宽时要保住“没有下划线就整段使用”。

鲲鹏的空表也集中在一个判断里。只拿掉流量广告位这一项，避免查询和下载各写一个例外。

菜单来自数据库。前端路由表删了组件之后，库里的菜单还在就会点进空白页，所以停用脚本和删页面分成两步。脚本不在这轮执行，避免没授权就改库。

## 怎样避开「不做」

- 不改 `mergex-datasyn`，不搬它的 Mapper，不改同步。
- 不改 `POST /trafficPlace/getTrafficPlace`，映射管理继续用它。
- 不改小时、预警、华为、消耗、熔断、填充的页面。小时报表只是继续调用已经放宽的解析。
- 不改 `report_kunpeng` 的表和查询列。
- 不改 React，不改 Mediatom 页面。
- 不改聚合配置里的 funlink 编辑限制。
- 不手改正式库。菜单脚本只提交到仓库。
