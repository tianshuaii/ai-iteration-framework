# 需求与注意事项：流量广告位下拉改查

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

ADX 报表和鲲鹏报表的「流量广告位」下拉，现在调用 `POST /trafficPlace/getTrafficPlace`。页面把选项值拼成「广告位 ID_流量广告位 ID」，同一个流量广告位 ID 会重复出现。ADX 报表查询前只保留带下划线的值，并取下划线后面那段去查。

流量广告位和供应商的对应关系，已经由定时任务同步到 MySQL 表 `publisher_traffic_place_link`。这张表只有供应商 ID 和流量广告位 ID。

鲲鹏报表的表 `report_kunpeng` 没有流量广告位列。请求里一带流量广告位，查询和导出现在直接返回空表。

多曝光报表是数据报表里的独立页面，菜单来自 `sys_route_permission`，查询接口是 `POST /report/multiImpressReport`，另有对应下载。

## 本次要做

### 页面

数据报表里的 ADX 报表、鲲鹏报表，筛选区「流量广告位」改成和应用包名一样的异步搜索。

- 每一行只显示流量广告位 ID。同一个 ID 只留一行。选中值就是这个 ID，不再拼广告位 ID。
- 搜索框提示只提 ID，中英文都改。不要再用默认的「名称/ID」。
- 没选供应商、搜索框也是空的：不发请求。
- 没选供应商、搜索框有字：只按关键字查。
- 选了供应商：无论搜索框有没有字，都只查这些供应商的流量广告位。供应商选择一变就再查一次。搜索框为空时，列出这些供应商下去重后的 ID。搜索框有字时，在这些供应商里按 ID 匹配。
- 一个关键字按包含匹配。用逗号、空格或回车分开的多个关键字按 ID 精确匹配。规则和应用包名一致。
- 已经选中的 ID 换供应商时不清空。搜索请求把已选 ID 带回，下拉里仍能看到它们。新查到的命中范围仍只含选中供应商的 ID。
- 广告位筛选不再收窄这个下拉。关联表里没有广告位 ID。
- 鲲鹏报表的下拉同样改。选中流量广告位后，表格数字不随这个 ID 变化，也不再变成空表。数按日期、供应商等其余条件出。

多曝光报表整页去掉。菜单里不再出现「多曝光报表」。点旧地址不能再进这个页面。

### 接口与保存

新增查询，不删除 `POST /trafficPlace/getTrafficPlace`。

- 新接口：`POST /trafficPlace/searchPublisherTrafficPlace`
- 请求字段：`publisherIdList`（供应商 ID 数组，可空）、`searchKey`（关键字，可空）、`trafficPlaceIdList`（已经选中的流量广告位 ID，可空，只为了回显）
- 返回字段：`trafficPlaceId`。同一个 ID 只返回一次。
- 三个条件都空：返回空列表。
- 只传了已选 ID、没有供应商也没有关键字：只回这些已选 ID，方便下拉还显示它们。
- 需要登录，和现有下拉接口一样。没选供应商时，不按当前账号可见供应商再收一层。

ADX 报表查询、导出仍用字段 `trafficPlaceIdList`。新选择只传流量广告位 ID 数组。请求里如果还是「广告位 ID_流量广告位 ID」，取第一个下划线后面的整段再查。没有下划线的整段就是流量广告位 ID。

鲲鹏报表查询、导出不再因为 `trafficPlaceIdList` 非空就返回空。这个字段不参与 `report_kunpeng` 的筛选。不先用流量广告位反查供应商再筛整张表。

多曝光的查询 `POST /report/multiImpressReport` 和下载 `POST /report/downloadMultiImpressReport` 去掉。下载任务名 `downloadMultiImpressReport` 一起去掉。

### 数据

不新建表，不改 `publisher_traffic_place_link` 的结构，不改定时同步。

菜单下掉：在 `mergex-manager` 增加一条 SQL，把 `sys_route_permission` 里组件名是 `FunlinkAnalyse` 的那条 `status` 从启用改成 `D`。不物理删除。不改其他菜单。这张表用 `status` 表示停用，没有 `yn`。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 打开 ADX 或鲲鹏，还没选供应商、也没输入 | 流量广告位下拉不请求，列表为空 |
| 已保存的筛选仍是「广告位 ID_流量广告位 ID」 | ADX 查询和导出取下划线后面的整段再查，结果和以前按流量广告位筛的一致 |
| 已保存的鲲鹏筛选带了流量广告位 | 不再返回空表，按其余条件出数 |
| 关联表里同一个 ID 对应多个供应商 | 下拉只出现一行 |
| 关联表里的空 ID | 不返回 |

## 不做

- 不删 `POST /trafficPlace/getTrafficPlace`，映射管理继续用它。
- 不改小时报表、预警、华为、消耗、熔断、填充分析的页面。
- 不改 `report_kunpeng` 的列，也不为它补流量广告位数据。
- 不改定时任务仓库 `mergex-datasyn`。
- 不改 React 前端，不改 Mediatom 页面。
- 不改聚合配置里的 funlink 编辑限制。
- 不手改正式库。菜单只通过管理端 SQL 停用。

## 注意事项

- 文件列表见改动范围。
- 没选供应商时，关键字能搜到关联表里任意供应商的流量广告位 ID。ADX 报表本身仍按原来的供应商权限出数，所以选了 ID 不一定有数。
- 某个供应商下 ID 很多时，搜索框为空也会一次返回这些 ID。这轮不另加条数上限，和应用包名搜索一样。
- 全量报表和小时报表共用同一段 ID 解析。小时报表页面不改。解析放宽后，小时报表如果收到不带下划线的 ID，也会拿去查，不再丢掉。
- 执行这条菜单 SQL 需要另外授权。本规格只规定脚本，现在不跑。
