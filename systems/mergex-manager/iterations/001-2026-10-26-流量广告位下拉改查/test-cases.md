# 测试用例

结果在验收前都算未测。执行记录写到 `test-log.md`，这里只写步骤。

## TC-01 按 ID 搜索并去重

- 前置：关联表里同一个流量广告位 ID 至少对应两个供应商。测试账号能打开 ADX 报表。
- 步骤：打开 ADX 报表。不选供应商。在流量广告位搜索框输入这个 ID 的一段。
- 期望：只出现包含这段的流量广告位 ID。该 ID 只有一行。行上没有广告位名称，也没有广告位 ID 前缀。再到鲲鹏报表输入同一段，行的内容和 ADX 一致。若输入两个用逗号分开的完整 ID，只返回这两个 ID，不返回仅仅包含片段的其他 ID。

## TC-02 选中供应商后空关键字也查

- 前置：某个测试供应商在关联表里有流量广告位，另一个供应商有不同的 ID。
- 步骤：在 ADX 报表选中第一个供应商。搜索框保持为空。
- 期望：发出新搜索接口。下拉只有第一个供应商的流量广告位 ID。看不到只属于第二个供应商的 ID。

## TC-03 不选供应商

- 前置：ADX 报表已打开。
- 步骤：清空供应商和搜索框。看是否发搜索请求。再输入一个关键字。
- 期望：两个都空时不发请求，下拉为空。有关键字后按关键字返回 ID，不要求先选供应商。

## TC-04 ADX 只传流量广告位 ID

- 前置：知道一个能在 ADX 报表里查出数的流量广告位 ID。
- 步骤：选中该 ID 并查询。看请求体和表格。
- 期望：`trafficPlaceIdList` 里是这个 ID，没有下划线拼接。表格只保留这个 ID 的数据。

## TC-05 旧拼接值仍能查

- 前置：有一条以前保存的筛选，值是「广告位 ID_流量广告位 ID」，后半段和 TC-04 是同一个 ID。
- 步骤：套用这条筛选并查询。
- 期望：报表不是空的。结果和 TC-04 只传后半段时一致。

## TC-06 鲲鹏选了也不筛这张表

- 前置：鲲鹏报表在当前日期和供应商下本来有数。
- 步骤：先不选流量广告位，记下表格有数。再用新搜索选中一个 ID，再次查询。
- 期望：表格仍有数，且和没选这个 ID 时相同。不再整表为空。

## TC-07 多曝光报表没了

- 前置：菜单 SQL 已在测试库执行。页面已是删掉多曝光之后的版本。
- 步骤：刷新菜单。再访问原来的多曝光地址。用接口工具调用原来的查询和下载。
- 期望：菜单没有「多曝光报表」。页面进不去。两个接口不再提供原来的报表。聚合配置里的广告源编辑仍能打开。

## TC-08 老接口和小时报表还在

- 前置：测试账号能进映射管理和小时报表。
- 步骤：打开映射管理，看流量广告位映射是否仍能列出。打开小时报表，不传流量广告位，按日期查询。
- 期望：映射管理仍走原来的 `POST /trafficPlace/getTrafficPlace`，列表还能用。小时报表能查出数。

## TC-09 换供应商不清空已选

- 前置：ADX 报表里已经选中一个流量广告位 ID。另一个测试供应商的关联表里没有这个 ID。
- 步骤：改选到另一个供应商。看已选值和这次下拉结果。
- 期望：已选 ID 还留在筛选里，下拉里仍能看到它。这次新查到的其他 ID 都属于新供应商。

## SR-01 ADX 不选流量广告位

- 前置：当前日期下 ADX 报表本来有数。
- 步骤：不选流量广告位，只按日期查询。
- 期望：能查出数。停止：不再改别的筛选项，不测导出。

## SR-02 小时报表按日期

- 前置：小时报表当前日期有数。
- 步骤：打开小时报表，按日期查询。
- 期望：能查出数。停止：不测预警、华为、消耗、熔断、填充，也不在小时报表上找流量广告位筛选项。
