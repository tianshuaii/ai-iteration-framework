# 需求与注意事项：下拉权限和鲲鹏空结果

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

001 给报表加了按供应商查流量广告位 ID 的新下拉。只传关键字时，查询没有按当前用户能看的供应商收口，能查出别人的流量广告位 ID。前端传进来的供应商列表，也没有和这个范围取交集。

鲲鹏报表的表里没有流量广告位这一列。选了这个条件后，列表、趋势和导出现在返回的是当前用户的全部鲲鹏数据，看起来像已经按它筛选过。

新下拉的请求对象写在服务接口里面，控制器也直接引用了这个内部类。

## 本次要做

### 页面

鲲鹏报表的筛选区不再显示流量广告位。查询、趋势和导出都不再带上 `trafficPlaceIdList`。综合报表和小时报表的这个筛选项保持现在的样子。

### 接口与保存

`POST /trafficPlace/searchPublisherTrafficPlace` 的请求字段不变，仍是 `publisherIdList`、`searchKey`、`trafficPlaceIdList`。请求类型从服务接口的内部类挪到 `model/vo/traffic/PublisherTrafficPlaceSearchReqVo`。

查询前先取出当前用户能看的供应商，和老下拉在没传供应商时用的是同一套：

- 没传供应商：只用这批能看的供应商。
- 传了供应商：和这批能看的供应商取交集。交集为空就返回空列表，不去查整张表。
- 能看的供应商本身就是空的：返回空列表。
- 超管能看的范围本来就是全部，取交集后仍按这个范围查。

关键字仍是一个走模糊、多个走精确。已选 ID 仍是精确匹配，并且也落在上面的供应商范围里。三个条件都空时仍返回空列表。

鲲鹏报表的列表、趋势和导出：请求里带了非空的 `trafficPlaceIdList` 时，按不支持的条件处理，返回空结果，不再返回未按这个条件过滤的全量数据。广告位、接入类型、包名这些原来就会返回空的条件保持不变。

### 数据

不新建表，不改关联表里的数据。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 只传关键字 | 只在当前用户能看的供应商里搜 |
| 传了别人的供应商 | 交集为空，返回空列表 |
| 已选 ID 不在能看的供应商下 | 不会出现在结果里 |
| 鲲鹏页面上一次选过流量广告位 | 页面不再带这个条件。别的调用方如果仍传非空列表，接口返回空 |
| 综合报表、小时报表 | 筛选项还在，查询走收口后的新下拉 |

## 不做

- 不改老接口 `getTrafficPlace` 的范围算法。
- 不改综合报表、小时报表的筛选项和查询。
- 不改流量广告位 ID 的原样匹配，不再按旧的下划线切开。
- 不改 `/report/fullReport` 里 `loginNum`、`payNum` 的补数查询。
- 不改多曝光报表的查询和下载。
- 不改定时任务仓库，不改菜单数据。
- 不给鲲鹏补这一列，也不改成返回一句「不支持」的新提示。

## 注意事项

- 具体文件见改动范围。
- 供应商范围用现有的供应商列表方法，不另写一套权限。
- 鲲鹏搜索页已经超过 300 行。这轮只藏筛选项并停止带上这个条件，不拆文件。
