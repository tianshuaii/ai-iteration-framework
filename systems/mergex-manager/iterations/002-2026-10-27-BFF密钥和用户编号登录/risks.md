# 风险与回退

| 风险 | 影响 | 怎样避免 | 怎样退回 |
|---|---|---|---|
| 密钥写在代码常量里，能看仓库的人都能看到 | 知道密钥就能用任意未停用用户的编号调用需要登录的接口 | 只放常量类。文档、日志和报错都不写这串值。比对失败和用户无效用同一种失败，不提示哪一步错了 | 换掉常量并重新发版。没有单独的开关 |
| 两个头都通过时不看登录会话 | 用户刚被退出，只要账号没停用，带对密钥仍能进 | 这是已定需求。停用用户仍拒绝 | 去掉拦截器里的新分支，恢复只认 token |
| 登录成功的 data 从字符串改成对象 | 还按整段 data 存储的旧页面会把对象存成凭证，后面请求带不上 token | 这次一起改共用存储。字符串返回仍整段存储，避免另一套旧接口被带坏 | 登录改回只返回 token 字符串。页面取值对两种形状都能用，可以后撤 |
| 本地环境文件已经有改动 | 提交时容易把环境开关一起带上 | 不改 `application.yml` 和页面开发地址。提交时排除这两处 | 不把这两处放进提交 |
| 没有数据库变更 | 没有要回滚的表结构 | 不写迁移 | 只回代码 |

没有要执行的迁移。退回就是恢复这两个仓库里本轮改过的文件。
