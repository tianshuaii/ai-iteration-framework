# 需求与注意事项：流量筛选移植到广告平台

范围见 [change-scope](./change-scope.md)。验收见 [acceptance](./acceptance.md)。当前进度只看 [status](./status.md)。

## 背景

连接管理的供应商“编辑流量筛选”页已使用 `TrafficDirectionV4` 提供完整流量筛选能力。本轮将同一套表单移植到 MergeX 广告平台账号新增/编辑页，表单字段保持不变，组件内权限 code 只替换为广告平台现有前缀。

只读源码核对确认：广告平台新增/编辑当前没有流量筛选字段、保存/回显逻辑或对应策略维度；本轮需要补齐真实保存、回显和生效，不能只复制前端组件。

## 本次要做

### 页面

- 以连接管理供应商页的 `TrafficDirectionV4` 为真源，保持字段、选项、默认值、模板能力和“更多定向规则”不变。
- 在广告平台账号新增/编辑页增加完整流量筛选区块。
- 权限前缀使用页面已有的 `platform:`；区块和更多规则后缀继续使用 `trafficTargeting` 和 `more`。
- 继续遵守现有新增/编辑表单的校验触发、必填星和布局约束，不顺手修改其他页面样式。

### 接口与保存

- 广告平台现有 `/platAccount/add|update|getById` 与 `/platAccount/oldAdd|oldUpdate|oldGetById` 两组路径都要支持同一套流量筛选契约。
- 新增和编辑都必须完成保存、回显和真实生效；不允许只显示表单、只保存前端状态或只覆盖其中一组接口。
- 表单对外使用独立 `trafficTargeting` 对象，其内部保持 `trafficDirectionSwitch` 和 `trafficDirectionVo`，不改变原表单字段语义。
- 现有 `policy_manage` 新增广告平台账号维度和 `plat_account_id`，不复用 `publisher_id`、`place_id` 等语义不匹配的字段。
- 本轮迁移只新增 `plat_account_id` 字段，不为该字段或广告平台账号策略新增表索引、唯一索引或联合索引；账号隔离和唯一挂载由业务读写逻辑保证。

### 数据

- 流量筛选默认关闭，`trafficDirectionSwitch` 默认为 `0`；开启后各规则沿用源组件默认值。
- 主规则保持设备品牌、安装列表、国家地区、流量包名。
- 更多规则保持网络类型、广告位类型、操作系统、SDK 版本、人群、日期和时间段。
- 页面回显所需的 `citySelectList`、`rangeDate` 继续按现有组件约定转换。
- 广告平台流量定向使用 `type=1` 的独立 `policy_manage` 主记录，`level` 使用新增的广告平台账号维度，`plat_account_id` 挂载账号主键。
- 每个 `policy_manage_link` 只引用该账号流量定向的 `policy_id`，关联记录可按规则数量生成多条。
- 关闭流量筛选时只清理该广告平台账号的 `type=1` 策略，不影响其他账号或其他策略维度。
- 维度使用具名常量表达，不在业务逻辑散落魔法值。

## 默认与老数据

| 场景 | 行为 |
|---|---|
| 新建账号 | 流量筛选默认关闭；开启后各规则沿用源组件默认值。 |
| 编辑已有账号 | 没有 `type=1` 流量筛选数据时按关闭回显；保存后再次打开必须完整回显。 |
| 不开启流量筛选 | 账号基础信息、过滤类型和 QPS 等现有保存行为保持不变。 |
| 关闭已有流量筛选 | 清理当前账号的流定向策略及其关联，其他账号和维度不受影响。 |

## 不做

- 不在广告位新增/编辑页增加流量筛选，不修改广告位载荷、服务或既有预算过滤。
- 不修改 Mediatom 页面或 React 前端。
- 不改变流量筛选内部字段、选项、默认值和源组件样式。
- 不顺手修改连接管理供应商页、广告源页已有流量筛选行为。
- 不新增、调整或删除 `policy_manage` 表索引；测试库中已经存在的索引不属于本轮自动清理范围。
- 本轮交付 `policy_manage` 新维度的迁移文件，但不执行正式库迁移、不修改正式数据，也不自动提交、推送、部署或启动服务。

## 注意事项

- 本轮涉及权限、接口、Schema 和两个仓库，继续使用 `strict` 档。
- 文件列表见改动范围，这里不重复路径。
