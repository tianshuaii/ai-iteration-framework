# 验收标准

| 编号 | 对应测试 | 标准 | 结果 |
|---|---|---|---|
| AC-01 | TC-01 | 广告平台账号新增/编辑出现完整流量筛选，字段、选项、默认值、模板和更多规则与源 `TrafficDirectionV4` 一致。 | 通过 |
| AC-02 | TC-02 | 目标区块只使用 `platform:trafficTargeting` 和 `platform:more`；无权限时对应能力不可用，模板新增权限保持原契约。 | 豁免：用户确认无权限分支接受豁免；残余风险为未使用真实低权限账号验证区块隐藏。 |
| AC-03 | TC-03 | `/platAccount/add|update|getById` 与 `/platAccount/oldAdd|oldUpdate|oldGetById` 均能保存和完整回显 `trafficTargeting`，规则真实生效。 | 通过 |
| AC-04 | TC-04 | 广告平台账号使用专用维度、`plat_account_id` 和 `type=1` 的独立 `policy_manage` 主记录；关联记录只引用对应 `policy_id`，开关或删除操作不影响其他账号或维度。 | 通过 |
| AC-05 | TC-05 | 不启用流量筛选时，广告平台账号的基础信息、过滤类型、QPS 及新老接口行为保持不变。 | 通过 |
| AC-06 | TC-06 | `mergex-manager` 提供只新增 `policy_manage.plat_account_id` 的广告平台账号维度迁移文件，不新增、调整或删除表索引；字段、实体、查询、服务和常量语义一致，旧维度数据不被改写。 | 通过 |
| AC-07 | TC-07 | 广告位新增/编辑及既有预算过滤没有本轮产品源码差异。 | 通过 |

结果通常使用“未测”“通过”或“未通过”。只有用户明确确认接受未验证项或残余风险时，才写 `豁免：用户确认……；残余风险……`，不能只写“豁免”“收口”或把没测过的项目写成通过。
