# 系统登记 Agent 入口

从本目录启动时，先读 [README.md](./README.md) 和 [00-register-system](../prompts/00-register-system.md)。

## 识别当前意图

- 用户要新增一套系统：按 `00-register-system.md` 做只读预检，先列出拟创建的路径和仍缺的信息。
- 用户点名已有系统：把对应 `systems/<system>/` 作为显式兜底入口，继续读该系统的 `AGENTS.md`，再按系统入口规则绑定一个轮次并读取其状态和任务。
- 用户只问某个系统的当前状态：只读该系统的恢复链，不修改文件；不要让用户手工提供轮次、阶段或任务。
- 用户没有点名系统且存在多套系统：列出登记表并请用户选择，不猜测当前系统。

Codex 自动加载的是任务工作目录祖先链上的 `AGENTS.md`。在终端里执行 `cd systems/<system>` 不会让已经创建的任务重新加载系统规则；日常迭代应直接以系统目录创建任务。

## 过程汇报

- 每次过程更新都写 `已完成：` 和 `下一步：`，不能只说明登记或检查结果。
- 可以继续时写 `无需你操作：` 并继续；需要用户补信息、授权或执行外部动作时写 `需要你：` 和一条明确动作。
- 回合结束时，用户可见的下一步必须与已登记系统的实际入口一致。

## 登记边界

- 系统目录名使用英文短横线格式；迭代主题仍使用中文。
- 已登记系统新建迭代时必须使用根目录 `scripts/create-iteration.rb`，禁止人工创建轮次目录或复制模板；脚本不可用时报告阻塞。
- 默认使用 `overview.md` 登记的真实仓库；原仓库有未提交修改时只登记 dirty 基线，不创建 worktree。只有另一 `implement` 或 `verify` 轮次登记使用同一仓库时，才允许用根目录 `scripts/create-worktree.rb` 创建到 `.worktrees/`。成果进入目标分支后，先取得拉取授权并用 `scripts/sync-worktree.rb` 同步、验证真实仓库，再使用 `scripts/cleanup-worktree.rb` 清理并恢复迭代文档中的原仓库路径；不得强删脏 worktree。
- 仓库只以绝对路径登记在系统 `overview.md`，不得复制源码或创建指向源码仓库的目录快捷方式。
- 知识库只能使用名为 `knowledge-base` 的绝对路径软链接；创建前必须确认目标存在。
- 未收到“开始执行”或“开始处理”时，只能给出登记方案，不能创建系统目录。
- 已登记系统的活动轮次必须读取 `stage-approvals.md`。规格和计划分别接受“需求审批通过”“计划审批通过”或目标与批准动作都明确的等价自然语言，再用 `scripts/record-stage-approval.rb` 分阶段记录；“自动审批需求和计划”可作为两阶段共同原话，但计划仍要等自身评审完成后绑定摘要。普通写入授权不能替代双审批门禁；“完成所有任务”只授权本轮实现任务和统一审核，“开始验收”与“确认收口”分别授权后续两段，联合表达才连续执行；所有这些授权都不含外部变更。
- 已登记系统先读根目录 `capabilities.yml`，再运行 `scripts/iteration-context.rb` 汇总所绑定轮次的 `capability-log.md` 和 `evidence/` 索引，按 `read_next` 读取必要正文；使用 `iteration-governor` 恢复能力门禁。首次整轮审核和返工增量审核都写入 `implementation-review.md`。verify 按风险档位执行受影响测试与受控浅功能回归，并复用未失效证据。MCP 默认只读，能力证据不能替代用户审批或扩大写入授权。
- 绑定后每个用户回合都把完整原话作为单个经过 shell 安全转义的参数传给 `scripts/iteration-context.rb <轮次目录> --intent SAFE_USER_MESSAGE`，按 `intent_route` 处理审批和任务范围；禁止拼接未转义原话，命中后不得要求用户换成固定口令。旧会话也必须重新读取该入口输出，不能沿用会话启动时缓存的示例文案。
- `iteration-context.rb` 返回 pending 问题时，必须同屏展示 `Qxx` 问题全文、推荐答案和可复制回复；未确认前不得写 `resolved` 或阶段评审通过，用户回答后保存确认原话。
